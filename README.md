# amamizu-lab（雨水ラボ）

調整池の**貯留追跡計算（厳密計算）**を行うツールです。
流入、池、放流施設の条件を入力すると、時刻ごとの水位・貯留量・放流量を計算し、許容放流量と容量の判定、グラフ、清書した PDF を出力することができます。
ブラウザで操作する画面（WebGUI）と、コマンド（`amamizu`）が使用できます。

## できること

- **流入**: 計画降雨（確率降雨強度式の5方式、後方集中型・中央集中型）、実測降雨（気象庁の10分値・時間値）、ハイドログラフ（CSV）
- **池**: 柱状の池、水位・面積・容量の表
- **放流施設**: オリフィス（長方形・円形、2段）、洪水吐、ポンプ
- **浸透**: 浸透施設（一定量差し引き）
- **寸法の算定**: 最大放流量が目標値になるオリフィスの寸法を求める
- **出力**: 許容放流量と容量の余裕の判定、時刻ごとの表（CSV）、要約、グラフ（PNG）、清書した PDF（`design_summary.pdf`）
- **WebGUI**: 条件を入力して試算し、複数の試算結果を比較したうえで、保存して出力する
- **そのほか**: 時間値の CSV から、浸透施設の雨水捕捉率と、時間降水量の基本統計を求める

計算の基準（強度式、放流の係数）は、手引の定数のファイル（`studies/_guideline/`）から選ぶか、手引を使用せずに値を直接入力します。
千葉県の手引（宅地開発等に伴う雨水排水・貯留浸透計画策定の手引、平成18年9月）の定数のファイルを同梱し、この手引の早見表と計算例で計算を検証しています（[計算の検証](#計算の検証)）。
他の基準も、同じ形式のファイルを作成すれば使用できます（[手引の定数](#手引の定数)）。

実測降雨に使う気象庁の観測値は、別のツール [jma-rainfall](https://github.com/nisefuruta/jma-rainfall) で取得します。

`studies/` には、このツールを使用した検証の例も収録しています（[検証の例](#検証の例)）。

## インストール

[uv](https://docs.astral.sh/uv/) と [Git](https://git-scm.com/) が必要です。

Windows では、PowerShell で winget を使ってインストールできます（管理者の権限は不要です）。

```powershell
winget install --id Git.Git --scope user
winget install --id astral-sh.uv --scope user
```

インストールした後は、PowerShell を開き直してください（開き直すまで、追加されたコマンドを使えません）。

リポジトリを clone し、uv で実行環境を作成します。

```powershell
git clone https://github.com/nisefuruta/amamizu-lab.git
cd amamizu-lab
uv sync
uv run amamizu --help   # コマンドの一覧が表示されれば、インストールできています
```

`uv sync` で WebGUI（NiceGUI）もインストールされます。

気象庁の観測値の取得に使用する `jma-rainfall` は、`pyproject.toml` の `[tool.uv.sources]` で、GitHub のリポジトリの特定のコミットを指定して参照しています。
`uv sync` のときに自動でインストールされます。
一緒に `jma-rainfall` コマンドもインストールされ、観測所の一覧（`uv run jma-rainfall stations`）を amamizu-lab のフォルダでそのまま表示できます。

### 日本語のフォント

グラフ（PNG）と PDF の出力には、次の表の日本語のフォント（TrueType）が必要です。

| OS | 使うフォント |
|---|---|
| Windows | Yu Gothic、Meiryo、MS Gothic（標準でインストールされている） |
| Linux | IPAexGothic。Ubuntu・Debian は `sudo apt install fonts-ipaexfont-gothic` でインストールする |
| macOS | IPAexGothic。[IPAex フォント](https://moji.or.jp/ipafont/)の ipaexg.ttf をインストールする |

Noto Sans CJK JP がインストールされていても、上の表のフォントのどれかが必要です。
フォントがなければ、out/ に何も出力せずにエラーで停止します。試験（`uv run pytest`）では、グラフと PDF を出力する試験をスキップします。
フォントをインストールした後も同じエラーになるときは、matplotlib のフォントの一覧のキャッシュ（`fontlist-*.json`）を削除してください。
キャッシュのフォルダはエラーの文に表示されます（Linux では通常 `~/.cache/matplotlib`）。

## 使い方

計算の条件と結果は、検討ごとのフォルダ（`studies/<年-月>_<題名>/`）に保存します。
条件は `study.json`、池の表などの入力ファイルは `input/`、計算結果は `out/` に保存します。

### WebGUI で使う

```powershell
uv run amamizu gui                         # http://127.0.0.1:8765/ をブラウザで開く。終了は Ctrl+C
```

`--port` を省略して 8765 が使用中または使用できないときは、次の空いている番号で起動し、その URL を表示します。

1. 一覧の「貯留追跡計算を行う」で題名を入力すると、検討フォルダ（`studies/<年-月>_<題名>/study.json`）が作成されます
2. タブ（全体、流入、池、放流施設、浸透、判定と実行）で条件を入力します
3. 「試算」で結果を WebGUI に表示し、「試算の比較」タブで試算結果どうしを比較します（ファイルには保存しません）
4. 「保存」で study.json と input/ の池の表を保存します。「保存して出力」は保存してから計算し、結果を `out/` に出力します（`amamizu study` と同じファイル）
5. 条件を変えた別のケースは、「⋮」のメニューの「複製する」で検討を複製し、ケースごとに出力します

詳しい使い方は [WebGUI](docs/WebGUI.md) にあります。

### コマンドで使う

```powershell
uv run amamizu study "studies\<検討フォルダ>"          # study.json の条件で計算し、結果を out/ に出力する（WebGUI の「保存して出力」と同じ）
uv run amamizu verify                                  # 計算結果が手引の値と一致するかを確かめる（強度式42式、早見表140件、浸透ありの容量の表112件）
```

| コマンド | 内容 |
| --- | --- |
| `gui` | WebGUI を開く（`--port`、`--studies`、`--no-browser`）。`--port` を省略して 8765 が使用中または使用できないときは、次の空いている番号で起動する |
| `study <検討フォルダ>` | study.json の条件で計算し、結果を `out/` に出力する |
| `rain` | 計画降雨を作成する（強度式の5方式、後方集中型・中央集中型、tc ごと）。CSV と PNG を出力する |
| `fetch <検討フォルダ> tenmin\|hourly` | 実測降雨に使う気象庁の10分値・時間値を取得して、地点ごとに `studies/_jma/<地点名>_<地点番号>/` に保存する。値がそろっていない日と暫定の値がある日だけを取得する |
| `periods tenmin\|hourly` | `studies/_jma/` に取得済みの日が続いている期間（実測降雨の期間の選択肢。WebGUI の一覧と同じ）を、地点ごとに新しい順に表示する。`--stations` で地点を選び（省略すると全地点）、`--output` で表をファイルに出力する |
| `verify` | 強度式、早見表、浸透ありの容量の表を、手引の定数の値と照合する。`--guideline` で手引の定数を選ぶ（既定 `chiba_2006`） |
| `capture`、`stats` | 時間値の CSV から雨水捕捉率、基本統計を求める。`capture` は欠測の時間（空欄）を除いて計算し、除いた時間数を表示する |

各コマンドの引数は `uv run amamizu <コマンド> --help` で確認できます。
計画降雨で寸法を決めてから実測降雨で確かめるまでの一連の手順は [手順例](docs/手順例.md)、実測降雨の取得の手順は [データの整理](docs/データの整理.md#設計の検討の実測降雨) にあります。

`studies/2026-09_追跡計算のテスト`（手引の解説 資料－4 の計算例）と `studies/2026-09_追跡計算のテスト(防災調節池等技術基準（案）)`（手引を使用しない検討）は、条件の書き方の見本として使えます。

## 手引の定数

`studies/_guideline/chiba_2006.json` に、千葉県の手引の値を収録しています。項目の説明と、他の基準のファイルを作るための雛形は `studies/_guideline/README.md` と `_template.json` にあります。

- 計算に使う値：資料－1 の確率降雨強度式（7地区×6確率年）、許容放流比流量の下限、観測所と地区の対応（観測所の位置が図5－2 のどの地区の範囲にあるかで決めたもの）
- 計算の照合に使う値：資料－2 の早見表（浸透なしの140マス）、第10条 表10－2（浸透ありの112マス）。`amamizu verify` と検証の例のレポートで、計算結果と照合します
- 表5－1 の流出率：検証の例のレポートで、流出係数から不浸透面積率を求めるのと、早見表と比べる行を選ぶのに使います。流入量の計算には使いません（流出係数は study.json に書きます）

キーごとの用途は [条件設定](docs/条件設定.md#手引の定数chiba_2006json) にあります。

他の基準を使うときは、同じ形の JSON を `studies/_guideline/` に置き、study.json の `guideline` で選びます（[条件設定](docs/条件設定.md#手引の定数chiba_2006json)）。ファイルを作らずに、放流の係数と強度式の係数を入力して計算することもできます（[条件設定](docs/条件設定.md#手引を使用しない検討)）。
早見表のない基準では、早見表の項目を書かなくてかまいません。

## 計算の検証

`uv run amamizu verify` で、計算が千葉県の手引の値を再現するかを確かめられます。
強度式の42式は表の値とのずれが0件、早見表の140件と浸透ありの容量の表の112件は ±0.7% 以内で一致します。
手引の解説 資料－4 の計算例－1 も、試験で再現を確かめています（[厳密計算](docs/厳密計算.md#10-手引との照合)）。

早見表のうち、我孫子地区、流出率0.90、許容放流比流量0.040 だけは、手引の表の 981 m^3/ha を、表の条件で計算した 928 m^3/ha に訂正して収録しています。981 は表の並びから外れていて、誤記とみられるためです（[厳密計算](docs/厳密計算.md#10-手引との照合)）。
解説 資料－4 の表－11（貯留追跡）は、流入と放流で平均する区間が合っておらず、時刻 t の貯留量に t〜t+10分に入る水を含んでいます。amamizu は区間をそろえて計算するので、表－11 より10分遅い時刻にほぼ同じ値になります（[厳密計算](docs/厳密計算.md#10-手引との照合)）。

試験と型の検査は、次のコマンドで実行します。

```powershell
uv run pytest            # 試験（確認済みの出力との一致を含む。約3〜6分）
uv run mypy              # 型の検査（domain と usecases。設定は pyproject.toml）
```

## 検証の例

`studies/` の次のフォルダは、このツールを使って、千葉県の観測所の記録で検証した例です。
計算の条件（study.json）と、使用した気象庁の観測値（`studies/_jma/`）を収録しています。

| フォルダ | 種類 | 内容 |
| --- | --- | --- |
| `studies/2026-09_貯留施設の検証` | 貯留施設の検証（`storage`） | 手引どおり1/50で計画した貯留施設に、官署4地点の約60年の降雨を与えると、何回溢れるかを確かめる |
| `studies/2026-09_降雨強度の検証` | 降雨強度の検証（`return_period`） | 県の10年確率式（t＝10分）の強度が、18地点の年最大10分間降水量では何年に1回にあたるかを確かめる |
| `studies/2026-09_千葉豪雨_<地点>`、`studies/2026-09_台風25号_<地点>` | 設計の検討（`design`） | 千葉豪雨（2026年8月13〜15日）と台風25号（9月20〜22日）の各18地点の10分値を、その地区の手引どおりに計画した貯留施設（寸法は安全側に丸める）に与えて計算する。`amamizu event-studies` で作成した36件 |

貯留施設の検証（`storage`）と降雨強度の検証（`return_period`）は、`amamizu study` で表とレポート（`out/report.md`。Markdown、CRLF）を出力します。WebGUI では、結果の表示だけができます。

```powershell
uv run amamizu study "studies\2026-09_貯留施設の検証"      # 表とレポートを out/ に出力する
```

検証の例で使うコマンドです。

| コマンド | 内容 |
| --- | --- |
| `study <検討フォルダ> --report <パス>` | レポートの保存先を変える。設計の検討にレポートはなく、`--report` を付けるとエラーになる |
| `event-studies <検討フォルダ>` | 貯留施設の検証（kind: storage）の降雨（`events`）ごと・地点ごとに、設計の検討を作成する（池とオリフィスは、その地区の手引どおりに計画した貯留施設の寸法を、安全側に丸めたもの）。`--studies` で検討を作成するフォルダを変更できる |
| `fetch <検討フォルダ> daily\|annual\|annual_max` | 日別値、年ごとの値、年最大値系列・観測史上順位を取得する。日別値は、値がそろっていない日と暫定の値がある日だけを取得する。年ごとの値（annual）と、年最大値系列・観測史上順位（annual_max）は、実行するたびに全部の年を取得する |
| `candidates <検討フォルダ>` | 時間値を取得すべき日（候補降雨の日）を `out/candidate_days_<地点>.txt` に出力する |

study.json の項目は [条件設定](docs/条件設定.md#検証の例)、気象庁からデータを取得する手順は [データの整理](docs/データの整理.md#貯留施設の検証の取得手順)、検討フォルダの中身（study.json、input/、raw/、out/）とコミットするかどうかは [データの整理](docs/データの整理.md#検討フォルダの区分) にあります。

## 構成

```
src/amamizu/
├── domain/        計算そのもの（numpy だけに依存。ファイルも通信も扱わない）
│   ├── intensity.py      確率降雨強度式（タルボット、シャーマン、久野・石黒、クリーブランド、久野・石黒 任意の n）
│   ├── design_storm.py   計画降雨（後方集中型、中央集中型）
│   ├── runoff.py         流出係数、合理式連続モデル
│   ├── outlet.py         オリフィス（長方形、円形。越流、オリフィス）と洪水吐
│   ├── pond.py           池（柱状、水位・面積・容量の表）と貯留追跡計算（台形公式）
│   ├── design.py         寸法を求める（必要洪水調節容量、オリフィスの寸法）
│   ├── infiltration.py   浸透施設（比浸透量、一定量差し引き）
│   ├── rainfall.py       降雨の区切り、継続時間ごとの雨量
│   ├── frequency.py      グンベル分布（モーメント法）
│   └── capture.py        雨水捕捉率
├── usecases/      検討の手順（domain と、ports.py のインターフェースだけに依存）
├── adapters/      外部との接続（手引の定数 JSON、study.json、検討フォルダのファイル、気象庁の観測値（studies/_jma/）の読み書き、気象庁からの取得、Markdown の出力）
├── app/           組み立て（study.json と入力から計算し、out/ に出力する。cli と gui が共通に使う）
├── gui/           WebGUI（NiceGUI）
└── cli.py         amamizu コマンド
studies/<検討>/    study.json（条件）、input/（設計の入力ファイル）、raw/（検証の例で、検証したい事象の集計）、out/（計算結果）
studies/_guideline/  手引の定数のファイル、雛形 _template.json
studies/_jma/        気象庁の観測値（地点ごと）
tests/             テストコード（pytest）。golden/ は確認済みの出力で、数値やレポートの意図しない変化を見つけるために使う
docs/              説明書（WebGUI の使い方、手順例、厳密計算の手順、study.json の条件の書き方、データの整理）
```

依存は外側から内側への一方向です（`tests/test_architecture.py` で確かめています）。

## 出典と利用規約

`studies/_jma/` の観測値の出典は、気象庁ホームページ「[過去の気象データ検索](https://www.data.jma.go.jp/stats/etrn/index.php)」です。
jma-rainfall で取得し、地点ごとのファイルにまとめています（形式は [データの整理](docs/データの整理.md)）。
検討フォルダの `raw/`、`tests/golden/` の表とレポートには、この観測値を集計・計算した値が入っています。
これらのデータを使うときは、気象庁ホームページの[利用規約](https://www.jma.go.jp/jma/kishou/info/coment.html)に従い、出典を記載してください。

`studies/_guideline/chiba_2006.json` と `tests/fixtures/kaisetsu_rei1/` の値は、千葉県「千葉県における宅地開発等に伴う雨水排水・貯留浸透計画策定の手引」（平成18年9月）とその解説から収録したものです。
