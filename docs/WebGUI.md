# WebGUI

study.json を手で書かずに、貯留追跡計算（厳密計算）の条件を入力し、結果を比較するための WebGUI（ブラウザで操作する画面）です。
計算は `amamizu study` と同じ処理を使います。
同じ study.json なら、WebGUI の「保存して出力」と `amamizu study` の out/ はバイト単位で一致します。

## 起動

`uv sync` で WebGUI（NiceGUI）もインストールされます。
開発用の依存を除いて環境を作るとき（`--no-dev`）は、`uv sync --no-dev --extra gui` で NiceGUI をインストールします。

```powershell
uv sync
uv run amamizu gui                         # http://127.0.0.1:8765/ をブラウザで開く
uv run amamizu gui --port 8800 --no-browser
uv run amamizu gui --studies D:\検討        # 検討のフォルダを変える（既定は ./studies）
```

`--port` を省略して 8765 が使用中または使用できないときは、8766 から 8784 まで順に確かめて、最初に空いていた番号で起動し、その URL を表示します。
`--port` で指定した番号が使用中または使用できないときは、エラーを表示して終わります。
NiceGUI がインストールされていないときは、インストールの方法を表示して終わります。
WebGUI は自分の PC（127.0.0.1）だけで開きます。
終了は、起動したターミナル（PowerShell など）で Ctrl+C です。

## 検討の一覧

studies/ の下の検討（study.json があるフォルダ）を一覧に表示します。
各行には、題名、種類、フォルダ名、作成日時（設計の検討）、最後に出力した日時（出力していなければ「未計算」）を表示します。
検証の例（降雨強度の検証、貯留施設の検証）を報告の順で先頭に置き、その後に設計の検討を作成日の新しい順に並べます（作成日は study.json の `created`。WebGUI で作るか複製すると書き込みます。ない検討はフォルダの作成日時）。
`created` を日時として読めない検討は、フォルダの作成日時で並べ、その行に `created` の値と書き方を表示します。
「貯留追跡計算を行う」で題名を入力すると、`studies/<年-月>_<題名>/study.json` を作ります（そのまま計算できる初めの条件が入っています）。
題名の空白は、フォルダ名では _ になります。
フォルダ名に使えない文字や、同じ名前のフォルダがあるときは作りません。

study.json を読めない検討（JSON の書き方の誤り、UTF-8 でない文字コード、kind がないなど）も一覧に表示し、その行に理由を表示します。
そうした検討を開くと、理由と直し方を表示します。study.json を読めた場合は、その中身も表示します。
study.json の項目の形が違う検討（区域 catchments がリストでない、など）を開いたときも、理由と直し方を表示します。
貯留施設の検証・降雨強度の検証は、`amamizu study` と同じ確認（不明な項目、必要な項目の不足、値の書き方）で誤りがあれば、開いたときに理由を表示します。
貯留施設の検証・降雨強度の検証は、out/ の出力の後に使った観測値（studies/_jma/）が変わっていれば、変わった期間と訂正を表示します。

複製と削除ができるのは設計の検討だけです。一覧の「⋮」のメニューか、検討の画面の右上の「⋮」のメニューで行います。

「複製する」は、条件（study.json と input/ の表）をコピーして新しい検討を作り、開きます。新しい検討の題名を入力してから作ります。
out/ はコピーしません。
study.json に不明な項目や値の書き方の誤りがあるときは、複製できません。
検討の画面で、保存していない変更があるときに複製すると、次のどちらかを選びます。

- 「変更を含めて複製」: 新しい検討に今の条件（池の表の変更を含む）を書きます。元の検討は保存した状態のままです
- 「保存してから複製」: 元の検討に今の条件を保存してから、同じ条件で新しい検討を作ります。池の表の保存で既存の CSV の内容が失われるときは、複製せずに止まります。先に「保存」で内容を確認してください

条件を変えた別のケースの出力が欲しいときは、ケースごとに複製して、それぞれの検討で「保存して出力」を行います。
エクスプローラーなどで検討のフォルダをコピーしても、そのまま検討として使えます（題名と作成日時は元のままで、out/ もコピーされます）。

削除の前にフォルダの中身（ファイルの数、out/ の有無）を表示して確認します。
フォルダは OS のごみ箱へ移るので、ごみ箱から元に戻せます。
ごみ箱へ移せなかったときは理由を表示し、「完全に削除する」で削除できます（元に戻せません）。

## 設計の検討

条件は6つのタブに分かれています。
入力するとすぐに右側のプレビュー（計画降雨と流入量、水位と容量、水位と放流量、比浸透量など）が変わります。

| タブ | 入力する条件 |
| --- | --- |
| 全体 | 題名、手引の定数（`studies/_guideline/` のファイルか「使用しない」）、放流の係数（「使用しない」のとき）、洪水到達時間 tc（計算の刻み） |
| 流入 | 計画降雨（手引の式か5方式、波形、継続時間、丸め）と区域、実測降雨（studies/_jma/ に取得済みの気象庁の10分値・時間値の、値の種類、地点、期間）と区域、またはハイドログラフの CSV（input/） |
| 池 | 柱状（面積と満水位）、または水位・面積・容量の表（行の追加・削除、input/ の CSV から読み込む（CSV に水位の列が必要。ないときはエラーを表示）、「CSV に保存」で池の表だけを保存先の CSV にすぐ書く）。面積と容量はどちらか一方を列ごと空欄にできる |
| 放流施設 | オリフィス（長方形・円形、2段）、洪水吐、ポンプ |
| 浸透 | 浸透なし、区域全体で1つ、区域ごと（区域がないハイドログラフは、浸透なし・浸透あり）。区域ごとなら区域名の見出しの下に区域ごとの欄が並ぶ。それぞれ設計浸透量・浸透強度・浸透施設（区域ごとなら浸透なし（無処理区域）も）を選ぶ。浸透強度は区域の面積があるときだけ選べる。浸透施設の影響係数は目づまり・地下水位・安全率 α の欄に入力し、施設を追加すると 0.9・0.9・1.0 が入る。欄の近くに雨水浸透施設技術指針［案］の値と、手引の定数のファイルの `infiltration_notes` の文を表示する |
| 判定と実行 | 与えたオリフィスで追跡するか、最大放流量が目標値になるオリフィスの寸法を求めるか。追跡するときは許容放流量（任意）、寸法を求めるときは目標の最大放流量。容量の余裕、追跡の終了時刻 |

実測降雨は、studies/_jma/ に取得済みの気象庁の10分値・時間値から、値の種類（10分値・時間値）→ 地点 → 期間の順に選びます。
流入を実測降雨に切り替えたときは、どれも選んでいない状態です。4つをすべて選ぶと、プレビューに降雨と流入量を表示します。
地点の選択肢は、選んだ値の種類を studies/_jma/ に取得済みの地点で、「千葉（千葉県）」のように都道府県を付けて表示します（study.json に書くのは地点名）。取得済みの地点がないときは、その旨を表示します。
地点を選ぶと、その地点の取得済みの期間（取得した日が続いている期間。新しい順）の一覧が表示されます。
一覧には日数、合計雨量、行のそろっていない日の数を表示し、入力して絞り込めます。取得済みの期間を読めないときは、欄の近くに理由を表示します。`amamizu periods` と同じ一覧です（[データの整理](データの整理.md#設計の検討の実測降雨)）。
期間を選ぶと、開始日・終了日に入ります。開始日・終了日は入力もでき、欄の右のアイコンから取得済みの日だけを選べるカレンダーも開けます。
開始日・終了日を選ぶまでは、流入のタブに「実測降雨の開始日・終了日を選んでください」と表示します。
ほかの地点・期間は、先に `amamizu fetch` で studies/_jma/ に取得します（欄の上に取得のコマンドを表示します。手順は [データの整理](データの整理.md#設計の検討の実測降雨)）。
欠測の区間と取得していない区間は 0 mm として計算し、「欠測の時間」「取得していない時間」をプレビューと試算の注意に表示します。

ハイドログラフの CSV は、input/ の CSV から選びます。流入をハイドログラフに切り替えたときは、どのファイルも選んでいない状態です。

説明が必要なボタンやタブは、マウスを重ねると説明を表示します。
入力の誤りは、そのタブの上に表示し、タブの名前に ⚠ を付けます。
入力や表の右にグラフを並べ、グラフの幅はブラウザの表示幅に合わせます。表示幅が狭いときは、グラフを入力や表の下に表示します。
誤りがある間は「試算」と「保存して出力」を押せません。「保存」は、値の書き方の誤り（整数の項目の 10.5 など）がなければできます。
入力の確認は `amamizu study` と同じ処理なので、WebGUI で通った条件はコマンドでも通ります。
整数の項目（tc、終了時刻、継続時間、丸めの桁、確率年）に 10.5 のような値を入力すると誤りになります。

### 試算の比較

「試算」は結果を WebGUI に表示するだけで、ファイルには保存しません。
結果のタブに、判定（O.K は緑、N.G は赤）、要約の表、流量（上に降雨強度）と水位のグラフ、注意（溢水、許容放流量の超過、前の刻みの放流量が池の水と流入の和を超えた刻み）を表示します。
オリフィスの寸法を求めるときは十数秒かかります。

試算の結果は、WebGUI（ブラウザのタブ）を開いている間保持します（タブを閉じると消えます）。
「試算の比較」タブに、試算ごとの主な値（最大放流量、最大水位、最大貯留量、余裕量、溢水量、判定）と、前の試算から変えた条件（池の表の変更を含む）を並べ、水位のグラフを重ねます。
「読み戻す」で、選んだ試算の条件を入力欄に戻せます。

### 手引の定数を使用しない検討

「全体」のタブの「手引の定数」で「使用しない」を選ぶと、手引の定数のファイルを使わずに計算します。

- 放流の係数（重力加速度 g、越流係数、オリフィスの流量係数）の入力欄が表示されます。初期値は 9.8、1.8、0.6 です。使用する基準の値を確認して入力してください
- 計画降雨は、強度式の種類と係数で入力します。手引の地区と確率年で選んでいた計画降雨は、同じ式の係数の入力に変わります
- 手引の定数を選び直すと、放流の係数の入力欄は消え、係数は手引の定数のファイルの値になります

新しい検討は、`studies/_guideline/` に `chiba_2006.json` があれば `chiba_2006` を選んだ状態で作ります。なければ「使用しない」で作ります。
計画降雨の地区と確率年の選択肢は、選んだ手引の定数のファイルにあるものです。

## 保存と保存して出力

「保存」は、study.json と input/ の池の表を保存します。計算と出力はしません。
計算の誤り（オリフィスがない、など）が残っていても保存できます。その study.json を `amamizu study` に渡すと、同じ誤りで止まります。
値の書き方の誤り（整数の項目の 10.5、study.json の数値の項目の true など）があるときと、study.json に不明な項目があるとき（削除して保存するかを確かめます）は保存しません。

「保存して出力」は、保存してから計算し、out/ に書きます（`amamizu study` と同じファイル。一覧は [厳密計算](厳密計算.md#9-設計の厳密計算を行う)）。
書き終えたら、清書した PDF（out/design_summary.pdf）を既定のアプリで開きます。
out/ への出力の途中でエラーになったとき（グラフを出力できないときなど）は、今回出力するファイルを out/ に残しません。前の実行の同じ名前のファイルと out/conditions.json も削除します。降雨のページで保存したファイルは残ります。
前の出力にあって今回の出力にないファイル（流入をハイドログラフに変えたときの rain.csv）は、書き終えたら削除します。削除するのは、前の出力のファイルとして out/conditions.json に記録したファイルだけです。
結果のタブに出力したファイルの名前を表示し、「フォルダを開く」で out/ をエクスプローラー（macOS は Finder）で開けます。

保存していない変更があるときは、題名の横に「未保存の変更あり」と表示します。
フォルダの下に、out/ の結果を作った条件（out/conditions.json）と今の条件（保存していない変更を含む）を比べた結果を表示します。

- 「out/: まだ出力していません」: out/ がないか、空
- 「out/: 今の条件で出力した結果です」: 今の条件と、out/ の結果を作った条件が同じ
- 「out/ の出力の後に、条件が変更されています（N 件）」: 開くと、変更した条件を「放流施設 オリフィス 幅（orifice.width_m）: 0.08 → 0.09」のように表示します（括弧は study.json の項目）
- 「out/ の出力の後に、使った観測値（studies/_jma/）が変わっています（N 件）」: 実測降雨を使う検討で、出力の後に使った観測値の行が増減したか、値か品質が変わったとき。開くと、変わった期間と訂正を表示します。「保存して出力」で、今の観測値の結果に作り直します
- 「out/: 出力の条件の記録がありません」: out/ にファイルがあり、out/conditions.json がない（降雨のページで保存しただけ、「保存して出力」が途中で失敗した、など）。「保存して出力」で出力し直すと比べられます

out/conditions.json を JSON として読めないときは、検討を開けません。開くと、そのファイルのパスと、削除してから出力し直す手順を表示します（`amamizu study` も同じ文を表示して止まります）。

入力した条件は、WebGUI（ブラウザのタブ）の中に持っているだけで、入力のタブ（全体・流入・池など）を移っても確定しません。study.json に書くのは「保存」「保存して出力」と、複製の「保存してから複製」だけです（「試算」は保存していない今の条件で計算します）。
保存していない変更があるときに、一覧へ戻るか上の「雨水ラボ amamizu」を押すと、変更を捨てて移動するかを確認するダイアログを表示します。ブラウザの再読み込みやタブを閉じるときは、ブラウザが確認します。

- study.json は項目の順をそろえ、UTF-8、CRLF で書きます。n の "3/4" のような分数の文字列はそのまま残します
- 読み込んだ study.json に不明な項目（amamizu が使わない項目。書き間違いなど）があるときは、検討の画面の上部に表示します。保存するには、それらの項目を削除して保存することを選びます
- 池の表の CSV は UTF-8（BOM 付き）、CRLF で書きます。表を変えていなければ書きません。既存の CSV を書き換えるときは、失われるもの（元の表の中身、計算に使わない列）を表示し、確認してから書きます

## 計画降雨と降雨記録

検討の画面の上部のボタンから、降雨の画面を新しいタブで開きます（検討の画面の保存していない変更は失われません）。
検討の画面で選んでいる（保存前を含む）計画降雨か降雨記録の条件を初期値にします。降雨の画面の戻るボタンは、そのタブを閉じて元のタブに戻ります。
ボタンの表示は流入に合わせて変わります。計画降雨なら「計画降雨」、実測降雨なら使う降雨記録（「降雨記録 千葉 10分値 2026-08-13〜2026-08-15」など。地点を選んでいないときは「降雨記録 （地点を選んでいません）」）です。
ハイドログラフのときはファイル名を表示し、押すと流入のタブを開きます。

降雨の画面は、画面の上で「計画降雨」と「降雨記録（実測降雨）」を切り替え、どちらも同じ形で表示します。

- 計画降雨: 強度式（手引の式の地区と確率年か、5方式）、降雨波形、継続時間、区間 tc、丸め（小数の桁）を選ぶ（`amamizu rain` と同じ）。
  手引を使用しない検討では、強度式の種類と係数を入力する
- 降雨記録: 実測降雨の値の種類（10分値・時間値）、地点、期間（検討の画面の流入のタブと同じ欄。選択肢は studies/_jma/ に取得済みの地点）と、区間 tc を選ぶ。
  初期値は検討の画面で選んでいるもの（保存前を含む）。10分値を tc ごとに合計する（貯留追跡計算の流入と同じ）
- 表示: 説明、総雨量と最大（降雨記録は日時も）、欠測の時間、ハイエトグラフ（棒グラフ）、区間ごとの表（降雨記録は区間の日時の列がある）
- 「out/ に保存」で、検討フォルダの out/ に CSV と PNG と、作り直すための条件（.json）を出力する。同じ名前のファイルがあれば上書きする（グラフを出せなければ、どれも残さない）。
  保存する名前の初期値は planned_rain（計画降雨）と observed_rain（降雨記録）。「保存して出力」の結果のファイル（rain.csv、route.csv など）と同じ名前では保存できない

ここで変えた条件は、検討の条件（study.json）には反映しません。
降雨記録から計画降雨に切り替えると、地区の初期値は降雨記録の地点が属する地区になります。

## 貯留施設の検証・降雨強度の検証

見るだけです（取得と計算は `amamizu fetch`、`amamizu study` で行います）。
条件（study.json の内容）、計算結果の表、レポート（`out/report.md` があるとき。図も描きます）を表示します。
貯留施設の検証の表は計算の順に並べ、選んだ表の目的を表の上に表示します（一覧は [データの整理](データの整理.md#出力する表)）。
降雨強度の検証は、開いたときに studies/_jma/ の年最大値系列・観測史上順位と raw/report_data.json から計算します。
`amamizu study` の後に study.json の条件を変えたときは、変えた条件を検討の名前の下に表示します（out/conditions.json と比べます）。
