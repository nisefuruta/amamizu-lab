# データの整理

貯留追跡計算（設計の検討）に使うデータの形式と保存先、気象庁の観測データの取得の手順を説明する。
検証の例（貯留施設の検証、降雨強度の検証）で使う取得の手順と整理の規則は、後ろの「[検証の例](#検証の例)」にまとめている。

## 検討フォルダの区分

検討は `studies/<年-月>_<題名>/` に1フォルダずつ置く。

| 保存先 | 中身 | コミット |
| --- | --- | --- |
| `study.json` | 検討の条件（[条件設定](条件設定.md)） | する |
| `input/` | 設計の検討の入力ファイル（池の表、ハイドログラフ）。利用者が用意する | する |
| `raw/` | 降雨強度の検証（検証の例）で確かめる事象の集計（[年最大値系列の標本](#年最大値系列の標本)）。手を加えない | する（改行コードを変換しない） |
| `out/` | 計算結果。`amamizu study` で作り直せる | しない |

手引の定数のファイルは `studies/_guideline/<名前>.json` に置き、study.json の `guideline` で選ぶ（[条件設定](条件設定.md#手引の定数chiba_2006json)）。
このフォルダは検討の一覧には出ない。

気象庁の観測値（日別値、時間値、10分値、年ごとの値、年最大値系列、観測史上順位）は、地点ごとに1か所の `studies/_jma/<地点名>_<地点番号>/` に置き、どの検討からも使う（コミットする。改行コードを変換しない。検討の一覧には出ない）。
どれも `amamizu fetch` が取得してここに保存し、`amamizu study`・`amamizu candidates`・`amamizu event-studies`・`amamizu periods` と WebGUI はここから読む。
設計の検討の実測降雨も、ここの10分値・時間値を使う（[設計の検討の実測降雨](#設計の検討の実測降雨)）。
ファイルの一覧は [studies/_jma/ のファイル](#studies_jma-のファイル) にある。

## 設計の検討の入力ファイル

設計の検討（`kind: design`）の入力ファイル（池の表、ハイドログラフ）は CSV（UTF-8。BOM 付きでもよい）で、`input/` に置く。
列名は study.json で指定する（省略時は下の表の列名）。
指定した列がない場合や、数値でない値・空欄がある場合は、エラーで止まる。
列名の前後の空白は無視する。

**池の表**（`pond.table`）は、水位・面積・容量を1行ずつ、池の底（最も低い水位）から順に書く。
最初の行が池底で、追跡は池が空の状態から始まる。
降雨の始めに水や土砂がある部分は、表に入れない（[厳密計算](厳密計算.md#高さの基準と池底とオリフィスの高さ関係)）。
面積と容量は、どちらか一方を省ける（列を置かないか、列をすべて空欄にする）。容量を省くと、面積から平均断面法で求める。
面積を省くと、結果の表に水面積の列を出力しない（追跡には容量だけを使う）。列の一部だけが空欄ならエラーで止まる。

| 列（既定の列名） | study.json の指定 | 内容 |
| --- | --- | --- |
| `水位_m` | `level_col` | 水位 m。絶対標高（T.P. など）でも相対標高でもよい。オリフィスと洪水吐の敷高も同じ基準で書く（[厳密計算](厳密計算.md#高さの基準と池底とオリフィスの高さ関係)） |
| `面積_m2` | `area_col` | その水位の水面積 m^2 |
| `容量_m3` | `volume_col` | その水位までの容量 m^3。最初の行は0。省くと V[i] = V[i-1] + (A[i-1] + A[i]) / 2 × (h[i] - h[i-1]) |

```csv
水位_m,面積_m2,容量_m3
16.0,0,0
17.0,1386,1198
18.0,1772,2772
19.0,2157,4736.5
```

水位と容量は、下の行ほど大きくする。
段のある池は、段の上下の水位を近づけた2行で表す（例: 26.00 m で 79 m^2、26.01 m で 18,700 m^2）。
行の間は線形補間する。

**ハイドログラフ**（`inflow_csv`）は、区切り（tc）ごとの流入量を時刻順に書く。
設計の検討の出力 `out/inflow.csv`（流出量の計算結果。浸透を差し引いた流入量）は、この形なのでそのまま使える（[厳密計算](厳密計算.md#9-設計の厳密計算を行う)）。

| 列（既定の列名） | study.json の指定 | 内容 |
| --- | --- | --- |
| `時刻_分` | `time_col` | 区切りの終わりの時刻 分。tc, 2tc, 3tc … と並べる |
| `流入量_m3s` | `q_col` | その時刻の流入量 m^3/s |
| （任意） | `rain_col` | その区切りの降雨強度 mm/hr。結果の表に書き写す |

時刻0の流入量は0とし、最後の行の次の時刻にも0を足して追跡する。
流入量が強度の大きい順に並んだ表を使うときは `"reverse": true` を書くと、値の並びを逆にして後方集中型にする（時刻の列はそのまま）。

## 設計の検討の実測降雨

**実測降雨**（`observed_rain`）は、`studies/_jma/` に取得した気象庁の10分値か時間値を、観測どおりの順序で区域に降らせる流入である。
区域（`catchments`）の面積と流出係数で、計画降雨と同じ合理式連続モデルの流入量にする（[厳密計算](厳密計算.md#4-流入量合理式連続モデル)）。

study.json には、地点・値の種類・期間を書く。4つの項目はどれも必ず書く（[条件設定](条件設定.md#設計の検討kind-design)）。

```json
"observed_rain": {"station": "千葉", "series": "tenmin", "start": "2013-10-15", "end": "2013-10-16"}
```

| 項目 | 書き方 |
| --- | --- |
| `station` | 地点名。`studies/_jma/` に取得済みの地点 |
| `series` | 値の種類。`tenmin`（10分値）か `hourly`（時間値） |
| `start`・`end` | 開始日と終了日。`2013-10-15` の形。その日の 0:00〜24:00 を含む |

WebGUI では、流入のタブで値の種類・地点を選び、取得済みの期間の一覧から選ぶか開始日・終了日を入力する（[WebGUI](WebGUI.md#設計の検討)）。

取得済みの期間は、取得した日が1日も空かずに続いている期間である。WebGUI の一覧と同じものを、コマンドで表示できる。

```powershell
uv run amamizu periods tenmin --stations 千葉                          # 千葉の10分値の期間（新しい順）
uv run amamizu periods hourly --output 時間値の期間.tsv                 # 時間値を取得済みの全地点。表にも書く
```

表示は地点ごとに、期間・日数・合計雨量（欠測の区間を除く）・行のそろっていない日の数である。
`--output` の表の列は `地点`、`開始日`、`終了日`、`日数`、`合計雨量_mm`、`そろっていない日`（UTF-8 BOM 付き、改行 CRLF。`.tsv` はタブ区切り）。
地点が取得済みでない、その値の種類を取得していない、同じ地点を2回指定した、のどれかであればエラーで止まり、表を書かない。

計算の仕方:

- 期間の値が `studies/_jma/` に1つもなければ、`amamizu fetch` で取得するよう示してエラーで止まる（その地点の値の種類のファイルはあり、期間の行がないときは、取得のコマンドも示す）
- 欠測の区間と、`studies/_jma/` に値のない区間（取得していない日、取得できなかった日）は 0 mm として計算する。
  「欠測の時間」「取得していない時間」として、要約と WebGUI の注意に書く。近くの地点の値などで埋めない
- 一部の日だけを取得した時間値（検証の例で、[候補降雨](#候補降雨の選定)の日だけを取得した時間値など）も、そのまま使える。取得していない日は「取得していない時間」になる
- 期間が長いと計算に時間がかかり、out/ のファイルも大きくなる（千葉の時間値 1967〜2026年の全期間で約3分、route.csv 約120MB、rain.csv 約220MB）。
  ふつうは降雨の前後を含む数日〜数か月を指定する。WebGUI のグラフは、点が多いときは区間ごとの最大の点だけを描く
- 時間値は、1時間の雨量を10分ずつ均等に配分する（[時間値と10分値の変換](#時間値と10分値の変換)）。10分値より強度の山が低くなる
- tc は10の倍数にする。10分値を tc ごとに合計して、その区切りの降雨強度にする
- 計算の時刻0分は、開始日の 0:00 である。要約と rain.csv には日時も書く

要約（`out/design_summary.md`）には、「実測降雨」（地点、値の種類、期間）、「観測値」（`studies/_jma/<地点名>_<地点番号>`）、「時刻0分」の行を書く。
`out/conditions.json` には、計算に使った観測値の記録を書く（[取得の方針](#取得の方針)）。

10分値は2008年以降しかない。それより前の降雨は時間値を使う。

手順（千葉 2013年10月15〜16日の10分値を使う例）:

```powershell
# 1. 10分値を studies/_jma/ に取得する（<検討> は設計の検討のフォルダ）
uv run amamizu fetch "studies\<検討>" tenmin --stations 千葉 --start 2013-10-15 --end 2013-10-16

# 2. WebGUI で、流入を「実測降雨」にし、値の種類（10分値）・地点（千葉）・開始日・終了日と区域を選ぶ
uv run amamizu gui
```

時間値は、取得する日を1行に1日ずつ（`2013-10-15` の形）書いた UTF-8 のファイルを `--dates-file` で指定して取得する（`uv run amamizu fetch "studies\<検討>" hourly --stations 千葉 --dates-file <日の一覧>`）。
`amamizu fetch` は、値がそろっていない日と暫定の値がある日だけを取得する（[取得の方針](#取得の方針)）。
WebGUI を使わないときは、study.json に `observed_rain` と `catchments` を書いて `amamizu study <検討>` を実行する（[条件設定](条件設定.md#設計の検討kind-design)。地点と期間の調べ方からの通しの例は [手順例](手順例.md#例2-実測降雨で確かめる)）。

## 気象庁の観測データ

取得そのものは、別のツール [jma-rainfall](https://github.com/nisefuruta/jma-rainfall)（`jma_rainfall` パッケージ）が行う。
`amamizu fetch <検討フォルダ> tenmin|hourly` は jma-rainfall で10分値・時間値を取得し、検討フォルダの親のフォルダ（`studies/`）の `_jma/` に地点ごとに保存する。
日別値、年ごとの値、年最大値系列の取得（`daily|annual|annual_max`）は、検証の例で使う（[検証の例の取得](#検証の例の取得)）。

## 取得の方針

気象庁のサーバへのアクセスは最小にする。

- 取得は2秒間隔で、200回ごとに60秒休止し、失敗が3回続いたら打ち切る（`jma_rainfall` の Pacer）。アクセス間隔は `--interval`（秒）で変えられる。
- 10分値・時間値は、要る日（値がそろっていない日と、暫定の値がある日）だけを取得する。
  - 10分値: 指定した期間（`--start`、`--end`）のうち、要る日だけを取得する。
  - 時間値: 取得する日の一覧（`--dates-file`。UTF-8 で、1行に1日を `2026-08-13` の形で書く。`{station}` は地点名に置き換わる）のうち、要る日だけを取得する。
- 観測日から `refresh_months` か月（`studies/_jma/config.json`。今の設定は1）の間に取得した値は暫定、それより後に取得した値は確定である。
  暫定の値は取得のたびに取り直し、値か品質が変われば上書きして `revisions.tsv` に記録する（準正常値・資料不足値が後日正常値に直ることがある）。
  確定の値と違う値を取得したときは、その行は書かず（ほかの行は書く）、その一覧を表示して終了コード1で終わる。
  取得した値で上書きするときは、`--accept-revisions` を付けて実行し直す（上書きした値は `revisions.tsv` に記録する）。
- 取得の経過と失敗の理由は標準エラーに表示する。失敗があれば、`amamizu fetch` は失敗の件数を表示して終了コード1で終わる。時間を置いて同じコマンドを実行し直す。
- 取得したデータは `studies/_jma/` に置いてコミットする。再計算ではサーバへアクセスしない。

`amamizu study`（実測降雨を使う設計の検討と、検証の例）と WebGUI の「保存して出力」は、使った観測値（種類・地点・読んだ期間ごとの行数、
値と品質から作った指紋、最後の取得日、暫定の値・準正常値・資料不足値の数）を `out/conditions.json` の「観測値」に記録する。
離れた期間を読んだときは期間ごとに記録する。
次の `amamizu study` と WebGUI は、この記録と今の `studies/_jma/` を比べ、行が増減した期間や値か品質が変わった期間を、
その期間の訂正（`revisions.tsv`）とともに表示する。

## SSL証明書

`amamizu fetch` は、サーバ証明書を Windows の証明書ストア（「信頼されたルート証明機関」）で検証する。
ブラウザと同じ証明書を信頼するので、社内網の UTM（FortiGate など）が SSL/TLS を検査している環境でも、UTM の CA 証明書が Windows に登録されていれば、設定なしで検証が通る。

証明書のエラー（`SSLError`、`CERTIFICATE_VERIFY_FAILED`）が出たときは、UTM の CA 証明書が Windows に登録されているかを確かめ、登録されていなければインストールする。
確認の方法とインストールの手順は、jma-rainfall の README の「[SSL証明書の問題](https://github.com/nisefuruta/jma-rainfall#ssl証明書の問題)」にある。

**一時的な対処:** 解決するまでの間だけ、`amamizu fetch` の `--disable_ssl_verify` で証明書の検証を無効にできる。
通信の相手を確かめないため、なりすましや改ざんを検出できない。信頼できるネットワークでだけ使い、常用しない。

## studies/_jma/ のファイル

`amamizu fetch` が書く。
ファイルはどれも UTF-8 で、改行は CRLF である（CSV・TSV は BOM 付き）。
`.gitattributes` で改行コードを変換しない設定にしてあるので、エディタで開いて保存し直さない。
地点のフォルダは `<地点名>_<地点番号>`（例: `千葉_47682`）で、地点番号は気象庁の「過去の気象データ検索」の地点番号（block_no）である。

| ファイル | 内容 | 主な列 |
| --- | --- | --- |
| `config.json` | 暫定とする期間 | `refresh_months`: 観測日からこの月数の間に取得した値を暫定とする（今の設定は1） |
| `fetch_log.tsv` | 取得の記録 | 取得日, 地点, block_no, 種類, 期間, 追加・同じ・上書きの行数, 出所 |
| `revisions.tsv` | 取り直して値か品質が変わった行の記録 | 取得日, 地点, block_no, 種類, 日時, 前の値, 新しい値, 前の取得日, 出所 |
| `<地点>/station.json` | 観測所 | 地点, block_no, pref（都道府県） |
| `<地点>/daily.csv` | 日別値（アメダス地点も） | 日付, 地点, block_no, 日合計_日別値_mm, 最大1時間_日別値_mm, 最大10分_日別値_mm, 日別値_品質, 取得日 |
| `<地点>/hourly.csv` | 時間値（取得した日だけ） | 日付, 時, 地点, block_no, 降水量_mm, 品質, 取得日 |
| `<地点>/tenmin/<年>.tsv` | 10分値（取得した日だけ。観測の年ごとのファイル） | 日付, 時分, 地点, block_no, 区間終了時刻, 降水量_mm, 品質, 取得日 |
| `<地点>/annual_a5.csv` | 年ごとの値 N時間降水量 | 年, 地点, block_no, 最大{h}時間/(mm), 最大{h}時間/月/日 時:分, 取得日 |
| `<地点>/annual_max.csv` | 年最大値系列（年最大10分間降水量と年最大1時間降水量。値のない年は空欄） | 年, 10分, 10分_品質, 1時間, 1時間_品質, 地点, block_no, 取得日 |
| `<地点>/rank.json` | 観測史上順位（観測史上1〜10位の値と、その統計期間） | 取得日と、要素（気象庁の表の名前）ごとの 1位〜10位の値（日付つき）と統計期間 |

`取得日` はその行の値を取得した日で、暫定か確定かを決める（[取得の方針](#取得の方針)）。
`fetch_log.tsv` の出所が「取り込み」の行の値は、`amamizu fetch` 以外で取得したファイルから取り込んだ値で、取得日はそのファイルの行が今の値と品質になったコミットの日付である（実際の取得はその日以前）。

地点名は一意でない（「金山」は4地点ある）。
フォルダ名に地点番号を含むので、同じ地点名の別の観測所の値は混ざらない。
`amamizu fetch` は、取得済みの地点名で別の観測所を取得しようとするとエラーで止まる。取得済みの観測所の続きを取得するときは、`--pref` で都道府県を指定する。
同じ地点名のフォルダが2つあると、計算と `amamizu fetch` は、その地点を読むときに2つのフォルダ名を表示して止まる。使わないほうのフォルダを `studies/_jma/` の外へ移す。

時刻の約束は次のとおりである。

- 時間値の「時」は1〜24で、その時刻に終わる1時間を表す（「時＝1」は0時〜1時）。
- 10分値の「時分」は00:10〜24:00で、その時刻に終わる10分を表す。1日は144コマである。

品質の値は `jma_rainfall` の定義による。

| 値 | 意味 |
| --- | --- |
| `normal` | 正常値 |
| `none` | 現象なし（`--`。0.0mm として扱う） |
| `quasi` | 準正常値（公表値の末尾に `)`。正常値と同等に扱う） |
| `insufficient` | 資料不足値（公表値の末尾に `]`。値そのものは信用できない） |
| `missing` | 欠測（`///` や `×`） |
| `doubtful` | 疑問値（`#`。値にかなり疑問があるため表示されていない） |
| `blank` | 空白（観測を行っていない、通信障害など） |

計算では、値がない品質（`missing`・`doubtful`・`blank`）を欠測として降水量を0とし、欠測の時間数やコマ数を結果の表に出力する。
品質が値のある品質なのに降水量が空欄の行や、降水量が数として読めない行があれば、読み込むときにエラーで止まる。
貯留施設の検証（検証の例）は日別値も使う。日別値のない地点はエラーで止まるので、`amamizu fetch <検討> daily` で日別値を取得する。

## 時間値と10分値の変換

追跡計算は10分刻みで行うため、時間値は10分ごとの強度に直す。

- **時間値→10分**：1時間の雨量 x mm を6区間へ均等に配分する。各10分の強度は x mm/hr になる。
- **10分値→時間値**：毎正時で区切って6コマずつ合計する。
- **10分値→強度**：10分の雨量を6倍して mm/hr にする。

時間値で計算した最大貯留率は、同じ降雨を10分値で計算した値より小さくなることがある。
貯留施設の検証（[検証の例](#検証の例)）の長期記録は時間値で計算し、開始日が `tenmin_from`（2008年）以降で最大貯留率が `tenmin_fill`（0.7）以上の降雨だけ10分値で計算し直して、その値を採る。
比較の表は `out/tenmin_check.tsv` に出力される。

## 検証の例

ここから後ろは、検証の例（`studies/` の貯留施設の検証と、降雨強度の検証）で使うデータと、その取得・整理の規則である。

### 使うデータ

気象庁「過去の気象データ検索」の次の表を使う。

| 表 | 期間 | 主な用途 |
| --- | --- | --- |
| 日別値 | 地点の観測開始から | 降雨の区切り、候補降雨の選定、最大1時間降水量（公表値） |
| 時間値 | 地点の観測開始から | 2007年以前を含む長期記録の追跡計算、3〜24時間の雨量 |
| 10分値 | 2008年以降 | 最大貯留率が `tenmin_fill` 以上の降雨（2008年以降）と途中の年の追跡計算、1地点ずつの降雨の再現 |
| 年ごとの値 N時間降水量（view=a5） | 1976年以降 | 継続時間ごとの雨量の照合 |
| 年ごとの値（年の合計・最大。view=""）、観測史上1〜10位の値 | 地点の観測開始から | 年最大10分間降水量の標本と統計期間 |

10分値は2008年より前がないため、約60年の長期記録は時間値で計算し、10分値は最大貯留率が `tenmin_fill` 以上の降雨を計算し直すのに使う。

### 検証の例の取得

検証の例では、10分値・時間値のほかに、日別値、年ごとの値、年最大値系列を `amamizu fetch <検討フォルダ> daily|annual|annual_max` で取得する。
アクセスの間隔、暫定と確定の扱い、失敗したときの扱いは、[取得の方針](#取得の方針) と同じである。

- 日別値: 要る日（値がそろっていない日と、暫定の値がある日）のある月だけを、月ごとにその月の要る日の最初の日から最後の日まで取得する（昨日まで。日別値のページは1か月ごと）。
  年ごとに書き、1日でも取得に失敗した年は書かない。失敗はなく行が1つも取れなかった年も、取得できなかった年として数える。
- 時間値: 追跡計算に必要な日（候補降雨の日）だけ取る。`--dates-file` を省略すると、検討フォルダの `out/candidate_days_<地点>.txt`（`amamizu candidates` が作る）の日のうち、要る日だけを取得する。
- 年ごとの値: 地点ごとに、N時間降水量（`--view a5`）の全部の年を取得する。取得に失敗した地点は書かず、残りの地点を取得する。
- 年最大値系列と観測史上順位: [年最大値系列の標本](#年最大値系列の標本) に書く。

`out/conditions.json` の「観測値」には、観測史上順位（`rank.json`）は表全体を1つとして記録する。
貯留施設の検証のレポートの冒頭には、使った観測値に含まれる準正常値（`)`）・資料不足値（`]`）の数を、計算に使った値と、
公表値との照合に使った年ごとの値に分けて書く。
降雨強度の検証のレポートには、標本に含まれる準正常値・資料不足値の数を書く。

### 貯留施設の検証の取得手順

貯留施設の検証（`studies/2026-09_貯留施設の検証`）は、次の順に取得して計算する。
コマンドの `<検討>` は検討フォルダのパスである。

```powershell
# 1. 日別値（地点ごとに年の範囲を指定）
uv run amamizu fetch <検討> daily --stations 千葉 館山 勝浦 銚子 --year-from 1961 --year-to 2025

# 2. 候補降雨の日を出力する（<検討>/out/candidate_days_<地点>.txt）
uv run amamizu candidates <検討>

# 3. 候補降雨の日だけ時間値を取得する
uv run amamizu fetch <検討> hourly --stations 千葉 館山 勝浦 銚子

# 4. 計算する（長期記録の表が out/ に出力される）
uv run amamizu study <検討>

# 5. 2008年以降で最大貯留率が tenmin_fill 以上の降雨の10分値を、降雨ごとに取得する
uv run amamizu fetch <検討> tenmin --stations 千葉 --start 2023-09-03 --end 2023-09-09

# 6. 年ごとの値（N時間降水量）を取得する
uv run amamizu fetch <検討> annual --stations 千葉 館山 勝浦 銚子 --view a5

# 7. 計算し直し、レポートを出力する（out/report.md）
uv run amamizu study <検討>
```

手順5で取得すべき降雨は、手順4の `out/long_events.tsv` のうち、開始日が `tenmin_from` 以降で最大貯留率が `tenmin_fill` 以上のものである（[条件設定](条件設定.md#conditions)）。
10分値が足りなければ、`amamizu study` が「10分値で計算し直す降雨ですが、10分値がそろっていません」と、地点・期間と取得のコマンドを示して止まる。

途中の年（2026年）は、その年の日別値を取得し（`--year-from 2026 --year-to 2026`。昨日まで）、候補降雨の10分値を手順5と同じ方法で取得する。
途中の年の候補降雨は `amamizu candidates` では出力しない。
`amamizu study` が「10分値がそろっていません」と示した期間を取得する。

`events` の降雨は、`stations` の地点ごとに、降雨の期間の10分値と、降雨の年の日別値を取得する。
計算には日別値も使うので、日別値のない地点はエラーで止まる。

```powershell
uv run amamizu fetch <検討> tenmin --stations <地点> … --start <開始日> --end <終了日>
uv run amamizu fetch <検討> daily --stations <地点> … --year-from <降雨の年> --year-to <降雨の年>
```

#### 出力する表

`amamizu study` は out/ に次の表を書く。WebGUI はこの順に並べ、表を選ぶと説明を表示する。
WebGUI での表の名前と説明には、study.json の値（`events` の名前と期間、長期記録の範囲、`partial_year` の期間、条件の値）を使う。
長期記録の1〜4は絞り込みの段階の順である。

| 表 | WebGUI での名前 | 内容 |
| --- | --- | --- |
| `event_<開始日>.tsv` | （降雨の名前）の各地点 | study.json の `events` の降雨ごとに、`stations` の地点ごとにモデル施設に与えて計算した結果。1行が1地点 |
| `screening.tsv` | 長期記録 1 絞り込みの件数 | 地点ごとに、対象期間の日数 → 降雨 → 基準雨量以上で計算した降雨 → 最大貯留率が `fill_ratio` 以上 → 10分値で計算し直した降雨 → 溢水 の件数。レポートの長期記録の節の表と同じ値 |
| `long_events.tsv` | 長期記録 2 時間値で計算 | 総雨量が基準雨量以上の降雨を、時間値で計算した結果。1行が1降雨。10分値を取得する降雨を選ぶのに使う途中の表 |
| `tenmin_check.tsv` | 長期記録 3 10分値で計算し直し | 2 のうち開始日が `tenmin_from` 以降で最大貯留率が `tenmin_fill` 以上の降雨を10分値で計算し直し、時間値の結果と並べた表 |
| `long_events_final.tsv` | 長期記録 4 最終の結果 | 2 のうち 3 で計算し直した降雨を、10分値の結果に置き換えた表（出所の列が「10分値」）。溢れた回数とレポートの長期記録の節の表はこの表による |
| `partial_year.tsv` | 途中の年（`partial_year` の期間） | `partial_year` の期間の降雨を10分値で計算した結果。長期記録の回数には含めない |
| `daily_missing.tsv` | 日別値の欠測日 | 日別値が欠測の日と、その日を含むか前後の降雨の組。計算したか、基準雨量までの差を判定の列に書く（[データの整合の確認](#データの整合の確認)） |

`amamizu study` は、計算の条件（study.json の内容）と出力したファイルの名前を `out/conditions.json` に書く。
前の出力にあって今回の出力にないファイル（study.json の `events` から削除した降雨の表、欠測の日がなくなったときの `daily_missing.tsv`）は、計算の最後に削除する。削除するのは、前の出力のファイルとして `out/conditions.json` に記録したファイルだけである。
`out/conditions.json` を JSON として読めないときは、そのファイルのパスを表示して止まる。そのファイルを削除してから実行し直す（前の出力にだけあるファイルは out/ に残る）。
計算がエラーで止まったときは、out/ を変えない。
出力の途中で失敗したときは、out/ に出力する今回の表・レポート・`conditions.json` と、前の出力にだけある表をすべて削除する。

`out/candidate_days_<地点>.txt` は時間値の取得に使う一覧で、`amamizu candidates` でいつでも作り直せる。

### 降雨の区切り

日別値の日降水量の並びを、無降水の日で区切って1つずつの降雨にする（`domain/rainfall.py` の `split_events`）。

- 降水量0の日が `dry_gap` 日（既定2日）以上続いたら、そこで別の降雨とする。
- 降雨の期間は、最初に降った日から最後に降った日までである。
- 区切りは記録全体で行い、そのあとで開始日が対象期間にある降雨を選ぶ。年の境目などの期間の端で降雨を途中から切らないためである。

- 日別値が欠測（値なし）の日は雨量0mm とするが、無降水の日には数えない（その日で区切らない）。
  降ったかどうかわからない日で区切ると、1つの降雨を分けて総雨量を小さく見積もるおそれがあるため、前後の降雨を1つにして判断する。
  欠測の日だけでは降雨を始めない。

計画降雨で満水にした池も、雨が止んで `dry_gap` 日で容量の1%以下まで下がる（`StorageStudy.left_after_dry`。レポートの長期記録の節に値を載せる）。
このため、前の降雨の水が池に残った状態を考えなくてよい。

### 候補降雨の選定

追跡計算に時間値が要るのは、溢れる可能性のある降雨と、レポートの長期記録の節の表に載せる降雨（最大貯留率が `fill_ratio` 以上）だけである。
池に入る水量は f×総雨量×面積 を超えないので、総雨量が次の値未満の降雨は、最大貯留率が `fill_ratio` に達しない。

```
基準雨量 mm = fill_ratio × 計画容量 m3 / (f × 10 × 開発面積 ha)
```

基準雨量以上の降雨を**候補降雨**とする（`StorageStudy.candidates`）。
`fill_ratio`＝1 なら、溢れる可能性のある降雨だけを計算する。レポートの長期記録の節の表に載せる降雨（最大貯留率が `fill_ratio` 以上）も計算するときは、1 より小さい値（0.5 など）にする。
レポートの長期記録の節の冒頭に、絞り込みの手順（降雨に区切る、総雨量で絞り込む、時間値で計算する）とその理由、基準雨量の計算例、地点ごとの件数（対象期間の日数、降水のあった日、降雨、計算した降雨とその日数、最大貯留率が `fill_ratio` 以上、溢水）を載せる。
降雨を区切る日数の裏付けとして、計画降雨で満水にした池が雨の止んだ `dry_gap` 日後に残す割合も載せる（`StorageStudy.left_after_dry`）。
計算した降雨の数が候補の数と合わなければ止める。

### データの整合の確認

計算の前に、表どうしが合っているかを確かめ、合わなければ計算を止める。

| 確認すること | 合わないとき |
| --- | --- |
| 対象期間（長期記録は開始年の1月1日〜`end_year` の12月31日、途中の年は `from`〜`to`）の日別値がすべての日にある | 「日別値が … 日ありません」で止まる |
| 候補降雨の日数×24時間の時間値がそろっている | 「時間値がそろっていません」で止まる |
| 時間値の合計が日別値の合計と1mm以内で一致する（欠測を含む降雨は除く） | 「時間値の合計 … が日別値の合計 … と 1mm を超えて違い」で止まる |
| 10分値が期間の日数×144コマそろっている | 10分値がないものとして扱い、その10分値を使う計算で止まる |
| 途中の年の10分値の合計が日別値と1mm以内で一致する（欠測を含む降雨は除く） | 「10分値の合計 … が日別値の合計 … と 1mm を超えて違い」で止まる |

時間値に欠測を含む降雨は、合計が日別値と合わなくても止めない。
その降雨は結果の表の「欠測時間」に時間数が出て、`amamizu study` の終わりに「注意:」として表示される。

日別値が欠測（値なし）の日は、雨量0mm として、降雨を区切らずに計算する（[降雨の区切り](#降雨の区切り)）。
その日に降った雨は総量に入っていない。
そこで `amamizu study` は、対象期間にある欠測の日を、その日を含むか前後 `dry_gap` 日以内にある降雨と組にして `out/daily_missing.tsv` に出力し、日数を「注意:」として表示する。
判定の列は「計算した」、「計算していない（基準雨量 ○mm まで ○mm）」、「前後○日に降雨なし」のどれかである。
基準雨量までの差は、欠測の日にどれだけ降っていたら計算する降雨に入ったかを示す。
降雨なしの日は、その日だけの降雨があってもわからない。

欠測の雨量は推測しない（仮定の雨量や近くの地点の値で埋めない）。
レポートには、降雨ごとに「欠測の時間」を書き添える。
対象は、期間内の計算に使った記録（時間値か10分値）の欠測と、前後 `dry_gap` 日のうち日別値が欠測の日の欠測（その日の時間値か10分値があればその欠測の時間、なければ終日）である。
レポートの最後の節には、欠測のある降雨を最大貯留率によらずまとめ、観測できた総量が基準未満で計算しなかった降雨のうち近くに日別値の欠測があるものも載せる。

時間値の合計が日別値と合わない年があれば、その地点の標本の開始年を遅らせる（study.json の `long_record.starts`）。
合わない降雨は途中までしか追えず、最大貯留率を小さく見積もるおそれがある。

### 継続時間ごとの雨量

継続時間 1, 3, 6, 12, 24時間の最大雨量は、次のように求める（`duration_depths`）。

- 3〜24時間は、毎正時で区切った1時間雨量の連続和の最大である。10分値しかない降雨も、毎正時の1時間雨量に直してから求める。
- 1時間は、毎正時で区切った値と、日別値表の最大1時間降水量（1分ずつずらした最大。公表値）の大きいほうを採る。
  降雨の日に公表値のない日（日別値が欠測の日など）があれば、その日数を表の `1h_公表値のない日` に書き、レポートの1時間の値に ※ を付ける。

貯留施設の検証の降雨（`events`）と候補降雨は、時間値・10分値の合計を日別値の合計と比べる。
1mm を超えて違うとき、欠測がなければエラーで止まり、欠測があれば「注意:」に表示して計算する。
日別値の最後の日にも雨がある降雨は、その後も降り続いた可能性があるので「注意:」に表示する（総量は記録の最後の日までで計算する）。

10分値で計算し直した降雨でも、継続時間ごとの雨量は時間値の値のままにする。
すべての降雨で同じ区切り方にそろえるためである。

求めた値は、長期記録の地点（`long_record` の `starts`）の、気象庁の年ごとの値「N時間降水量」（1976年以降。`studies/_jma/<地点>/annual_a5.csv`）と照合する（`usecases/published_check.py`）。
継続時間ごとに、計算で1/50を超えた地点と年の組と、公表値で1/50を超えた組が一致するかを確かめる。
一致しない継続時間があれば、「注意:」に、公表値だけが超えた地点・年と、計算だけが超えた地点・年を表示する。
公表値が数として読めない地点・年と、公表値の行がない地点・年は照合せず、「注意:」にその一覧を表示する。
公表値は2002年以前が毎正時で区切った値（1mm単位）、2003年以降が10分間隔で求めた値なので、個々の値は計算と一致しない場合がある。

### 貯留施設の検証の降雨ごと・地点ごとに、設計の検討を作る

`amamizu event-studies <貯留施設の検証>` は、貯留施設の検証（`kind: storage`）の `events` の降雨ごと・地点ごとに、
設計の検討 `studies/<年-月>_<降雨>_<地点>/` を作る（例: `2026-09_千葉豪雨_千葉`。千葉豪雨と台風25号の各18地点で36件）。
地点は `events` の `stations` の地点である。
流入は実測降雨で、各検討の study.json の `observed_rain` に、地点・`series`（`tenmin`）・降雨の期間（`start`・`end`）を書く。
同じ名前の検討のフォルダがあるときは、作らずに止まる。
期間の10分値がそろっていない地点があれば、取得のコマンド（`amamizu fetch <検討フォルダ> tenmin --stations <地点> --start <開始日> --end <終了日>`）を示して止まる。

池とオリフィスは、地点が属する地区のモデル施設（開発面積1ha、f＝0.8、深さ2.0m。安全側に丸めた寸法。[条件設定](条件設定.md#池の条件)）にする。

許容放流量は地区の下限の許容放流比流量×1ha（館山・勝浦地区は 0.035 m^3/s、ほかは 0.025 m^3/s）にする。
流入を手引の計画降雨にすると、どの地区も O.K（余裕 0.35〜1.46 m^3）になる。
貯留施設の検証の表（`out/event_<開始日>.tsv`）と同じモデル施設・同じ計算なので、最大貯留率と溢水量は表と一致する。

### 年最大値系列の標本

降雨強度の検証（`studies/2026-09_降雨強度の検証`）は、次のファイルを使う。

| ファイル | 内容 |
| --- | --- |
| `studies/_jma/<地点>/annual_max.csv` | 地点ごとの年最大10分間降水量と年最大1時間降水量（値と品質） |
| `studies/_jma/<地点>/rank.json` | 観測史上1〜10位の値と、その統計期間 |
| 検討の `raw/report_data.json` | 検証したい事象（千葉豪雨）の地点ごとの集計。計算では地点、種別、最大10分_mm だけを使う |

`annual_max.csv` と `rank.json` は `amamizu fetch <検討フォルダ> annual_max --stations <地点> …` で取得する。実行するたびに、地点ごとに年ごとの値（view=""）と観測史上順位を1回ずつ取得する。
年最大値系列は全部の年を取り直し、ほかの種類と同じ規則で書く（観測年の12月31日から `refresh_months` か月の間に取得した年の値は暫定）。
見出しに「降水量」「最大」「10分間」（または「1時間」）を含む列を使い、値の記号は品質にする（`)` 準正常値、`]` 資料不足値、空欄 blank、`×`・`///` missing）。
観測史上順位は、取得のたびに `rank.json` を置き換える。統計期間の開始は、要素「日最大10分間降水量 (mm)」の統計期間から読む。

年最大10分間降水量の標本は次の規則で作る（`usecases/return_period_study.py`）。

- 観測史上1〜10位の値の統計期間の内側に限る。
- 完全な暦年に限る。統計期間の開始月が1月でない年は除く。12月だけ観測した年の「年最大」は小さい側へ偏るためである。
- 検証したい年（2026年）は当てはめに入れない（`last_year` まで）。
- 値は公表値のまま使う。
- 範囲内に値のない年（annual_max.csv にない年、値が空欄の年、品質が `missing`・`doubtful`・`blank` の年）があれば、その年を示してエラーで止まる。
