# 手順例

amamizu（CLI）で検討を行う手順を、2つの例で通して示す。

- **例1 調整池の厳密計算**：計画降雨で調整池を計算し、池とオリフィスの寸法を決めて、成果（`out/design_summary.pdf` など）を出力する。
- **例2 実測降雨で確かめる**：例1で決めた調整池に、気象庁の10分値（台風25号の千葉）を与えて計算する。降雨データの取得から示す。

study.json の項目の意味は [条件設定](条件設定.md#設計の検討kind-design)、出力ファイルの内容は [厳密計算](厳密計算.md#9-設計の厳密計算を行う)、入力ファイルの形式は [データの整理](データの整理.md#設計の検討の入力ファイル) にある。
この文書では、それらを使う順序と、値の決め方を示す。
同じ計算は WebGUI（`amamizu gui`）でもできる（[WebGUI](WebGUI.md)）。

コマンドは amamizu-lab のフォルダで実行する。
例のコマンドは Windows の PowerShell で書いた。
macOS・Linux では、`New-Item -ItemType Directory` を `mkdir -p`、`Copy-Item` を `cp` にし、パスの区切りを `/` にする。
`uv run` で始まるコマンドは同じである。
グラフと PDF には日本語のフォントが要る（[README](../README.md#日本語のフォント)）。
例2の10分値は、`amamizu fetch` で気象庁から `studies\_jma\` に取得する（[データの整理](データの整理.md#設計の検討の実測降雨)）。
例の数値は、この文書の手順どおりに計算した結果である。

## 例1 調整池の厳密計算

千葉地区の開発区域 2.0 ha（流出係数 0.8）に調整池を設け、1/50 の計画降雨で池とオリフィスの寸法を決める例である。

### 1 材料をそろえる

計算に必要な値と、その決め方は次のとおりである。

| 値 | 例の値 | 決め方 |
| --- | --- | --- |
| 開発面積 | 2.0 ha | 計画図から求める |
| 流出係数 f | 0.8 | 手引 表5－1 により、不浸透域1.0・浸透域0.6 を面積で加重平均する（[条件設定](条件設定.md#流出の条件)）。不浸透面積率50%なら 0.8 |
| 地区 | 千葉 | 敷地の位置が手引 図5－2 のどの地区の範囲にあるかで決める。強度式はこの地区の式を使う |
| 確率年 | 50 | 手引の計画の確率年 |
| 洪水到達時間 tc | 10 分 | 計算の刻みにもなる（[厳密計算](厳密計算.md#2-洪水到達時間-tc-と計算の刻み)） |
| 許容放流量 | 0.05 m^3/s | 許容放流比流量 × 開発面積（手引 第5条(3)）。千葉地区の下限 0.025 m^3/s/ha × 2.0 ha |
| 池の形 | 下の表 | 計画図から、水位ごとの水面積を読む |
| オリフィスの敷高 | T.P. 10.0 m | 池の表の水位と同じ基準で書く。例では池底と同じ高さ |

池の表は、水位と水面積を池底から順に書く。
例では、水位と敷高を計画図と同じ絶対標高（T.P.）で書いた。
池底を0とする相対標高で書いてもよく、すべての高さを同じ基準で書けば、水位以外の結果は同じになる。
池底が敷高より低い池や、降雨の始めに水がある池の書き方は、[厳密計算](厳密計算.md#高さの基準と池底とオリフィスの高さ関係)にある。
容量の列を省くと、面積から平均断面法で求める。

### 2 検討フォルダを作る

```powershell
New-Item -ItemType Directory "studies\2026-09_○○団地_調整池\input"
```

`studies\2026-09_○○団地_調整池\input\pond.csv`（UTF-8）に池の表を書く。
最初は、池底 T.P. 10.0 m、満水位 T.P. 12.0 m、面積 1,000〜1,200 m^2 の池で試す。

```csv
水位_m,面積_m2
10.0,1000
10.5,1050
11.0,1100
11.5,1150
12.0,1200
```

### 3 オリフィスの寸法を求める

`studies\2026-09_○○団地_調整池\study.json` に条件を書く。
`mode: size_orifice` にすると、最大放流量が `target_q_m3s`（許容放流量）になるオリフィスの寸法を求めて計算する。
オリフィスには敷高だけを書く。
`guideline` は使う手引の定数で、必ず書く（`chiba_2006` は `studies/_guideline/chiba_2006.json`。[条件設定](条件設定.md#studyjson-の共通の項目)）。

```json
{
  "kind": "design",
  "title": "○○団地 調整池",
  "guideline": "chiba_2006",
  "tc_min": 10,
  "rain": {"guideline": {"district": "千葉", "return_period": 50}, "shape": "rear"},
  "catchments": [{"name": "開発区域", "area_ha": 2.0, "f": 0.8}],
  "pond": {"table": {"file": "input/pond.csv"}},
  "orifice": {"sill_m": 10.0},
  "mode": "size_orifice",
  "target_q_m3s": 0.05
}
```

```powershell
uv run amamizu study "studies\2026-09_○○団地_調整池"
```

結果の要約は `out\design_summary.md` にある。
この池では、要約に次の行が出て、判定は N.G になった。

| 項目 | 値 |
| --- | ---: |
| オリフィス | 敷高 10.000 m、長方形 幅 0.1162 m、高さ 0.1162 m |
| 池の容量の不足 | 入力の池（容量 2200.0 m^3）では、最大放流量を許容放流量にするオリフィスで溢れる。水深はそのままで面積を 1.039 倍（容量 2284.7 m^3、不足 84.7 m^3）にすると溢れない。（以下略） |
| 判定（溢水） | N.G（入力の池では溢れる。面積を 1.039 倍にすると溢れない） |

### 4 池を広げて計算し直す

要約の倍率（1.039倍）より余裕を持たせ、各水位の面積を 70 m^2 ずつ広げて（容量 2,340 m^3）、pond.csv を書き直す。

```csv
水位_m,面積_m2
10.0,1070
10.5,1120
11.0,1170
11.5,1220
12.0,1270
```

同じコマンドで計算し直すと、オリフィスは幅・高さ 0.1168 m、最大水位 11.9589 m、判定は O.K になった。

### 5 オリフィスの寸法を決めて確かめる

求めたオリフィスの寸法を、1mm 単位で切り捨てて 0.116 m にする。
切り上げると、最大放流量が許容放流量を超えるためである。
study.json を、決めた寸法で追跡する形（`mode` を書かない。既定の `route`）に書き直す。

- `mode` と `target_q_m3s` を削除する
- `orifice` に `width_m`・`height_m` を書く
- `allowable_q_m3s` に許容放流量を書く（最大放流量が超えたら判定が N.G になる）
- 容量の余裕を判定するなら `judge.storage_margin_m3` を書く（例では 30 m^3）

```json
{
  "kind": "design",
  "title": "○○団地 調整池",
  "guideline": "chiba_2006",
  "tc_min": 10,
  "rain": {"guideline": {"district": "千葉", "return_period": 50}, "shape": "rear"},
  "catchments": [{"name": "開発区域", "area_ha": 2.0, "f": 0.8}],
  "pond": {"table": {"file": "input/pond.csv"}},
  "orifice": {"sill_m": 10.0, "width_m": 0.116, "height_m": 0.116},
  "allowable_q_m3s": 0.05,
  "judge": {"storage_margin_m3": 30}
}
```

```powershell
uv run amamizu study "studies\2026-09_○○団地_調整池"
```

| 項目 | 値 |
| --- | ---: |
| 最大放流量 | 0.0494 m^3/s（1450 分） |
| 最大水位 | 11.9687 m（1450 分） |
| 最大貯留量 | 2301.1 m^3 |
| 容量（満水位 12.000 m まで） | 2340.0 m^3 |
| 余裕量（容量 - 最大貯留量） | 38.9 m^3（余裕率 1.7%） |
| 判定（溢水） | O.K |
| 判定（放流量） | O.K（許容放流量以下） |
| 判定（容量の余裕） | O.K（余裕 30 m^3 以上） |
| 判定（総合） | O.K |

判定が N.G なら、4 に戻って池を広げる。

### 6 成果

成果は `out\` に出力される。

| ファイル | 使い方 |
| --- | --- |
| `design_summary.pdf` | 清書。要約の表、グラフ3枚、時刻ごとの追跡の結果の表（A4） |
| `design_summary.md` | 要約の表とグラフ |
| `route.csv` | 時刻ごとの追跡の結果（解説 資料－4 の表－11 にあたる） |
| `inflow.csv` | 流出量の計算結果（解説 資料－4 の表－9 にあたる） |
| `rain.csv` | 計画降雨 |
| `hydrograph.png`、`water_level.png`、`pond_curves.png` | 降雨と流入量・放流量、水位、池と放流施設の特性のグラフ |
| `conditions.json` | 出力を作った条件。WebGUI が、出力の後に変えた条件を表示するのに使う |

`out\` はコミットしない（`amamizu study` で作り直せる）。
コミットするのは study.json と `input\pond.csv` である。

## 例2 実測降雨で確かめる

例1の調整池に、2026年9月の台風25号で千葉（気象台）が観測した10分値を与え、溢れるかを計算する。
流入を計画降雨（`rain`）から実測降雨（`observed_rain`）に替えるだけで、池とオリフィスは例1と同じである。

### 1 地点と期間を決める

気象庁の「過去の気象データ検索」（<https://www.data.jma.go.jp/stats/etrn/index.php>）で、地点と降雨の期間を調べる。

1. 「都府県・地方を選択」で都道府県を、「地点を選択」で敷地に近い地点を選ぶ。降水量を観測している地点（官署・アメダス）を選ぶ。
2. 年と月を選び、「日ごとの値を表示」で、その月の日降水量を見る。
3. まとまった雨が降り始めた日から、降水量が0になった日までを期間にする。台風25号の千葉は、9月19日 1.0 mm、20日 109.5 mm、21日 309.5 mm、22日 0.0 mm だったので、20〜22日にした。

期間は**日付**（YYYY-MM-DD）で指定する。
指定した日の 0:00〜24:00 の10分値をすべて取得し、計算もその範囲を使う。
追跡は、既定で期間の終わりから18時間後まで行う（study.json の `end_min` で変えられる）。

地点名は、`jma-rainfall stations` の一覧でも確かめられる（`jma-rainfall` コマンドは amamizu-lab の `uv sync` でインストールされる）。
同じ名前の地点が他の都道府県にあるときは、3 の `amamizu fetch` に `--pref`（都道府県）を付ける。

```powershell
uv run jma-rainfall stations --pref 千葉県
```

10分値は2008年以降しかない。
それより前の降雨は時間値（`series` を `hourly`）を使う（[データの整理](データの整理.md#設計の検討の実測降雨)）。

### 2 検討フォルダを作る

新しい検討フォルダを作り、例1の池の表をコピーする。
WebGUI では、例1の検討の「⋮」のメニューの「複製する」で、study.json と input/ をコピーした検討を作れる（[WebGUI](WebGUI.md#検討の一覧)）。
コマンドでは次のように作る。

```powershell
New-Item -ItemType Directory "studies\2026-09_○○団地_調整池_台風25号\input"
Copy-Item "studies\2026-09_○○団地_調整池\input\pond.csv" "studies\2026-09_○○団地_調整池_台風25号\input\"
```

### 3 10分値を取得する

`amamizu fetch` で、千葉の10分値を `studies\_jma\千葉_47682\` に取得する。
1つ目の引数は検討フォルダで、その親のフォルダ（`studies\`）の `_jma\` に保存する。

```powershell
uv run amamizu fetch "studies\2026-09_○○団地_調整池_台風25号" tenmin --stations 千葉 --start 2026-09-20 --end 2026-09-22
```

10分値は `studies\_jma\千葉_47682\tenmin\2026.tsv` に入る（観測の年ごとのファイル）。
期間のうち、値がそろっていない日と暫定の値がある日だけを取得する（[取得の方針](データの整理.md#取得の方針)）。
取得に失敗した日があれば、失敗の件数を表示して終了コード1で終わる。
時間を置いて同じコマンドを実行すると、そろっていない日を取得する。

取得済みの期間は `amamizu periods` で確かめる（WebGUI の期間の一覧と同じ）。

```powershell
uv run amamizu periods tenmin --stations 千葉
```

### 4 study.json を書いて計算する

例1の study.json から `rain` を削除し、`observed_rain` に地点・値の種類・期間を書く。
`start`・`end` は取得した期間と同じ日付にする。
`judge`（容量の余裕の判定）も削除する。

```json
{
  "kind": "design",
  "title": "○○団地 調整池（台風25号 千葉）",
  "guideline": "chiba_2006",
  "tc_min": 10,
  "observed_rain": {"station": "千葉", "series": "tenmin", "start": "2026-09-20", "end": "2026-09-22"},
  "catchments": [{"name": "開発区域", "area_ha": 2.0, "f": 0.8}],
  "pond": {"table": {"file": "input/pond.csv"}},
  "orifice": {"sill_m": 10.0, "width_m": 0.116, "height_m": 0.116},
  "allowable_q_m3s": 0.05
}
```

WebGUI では、流入のタブで「実測降雨」を選び、値の種類（10分値）、地点（千葉）を選び、取得済みの期間の一覧から降雨の期間を選ぶ（[WebGUI](WebGUI.md#設計の検討)）。

```powershell
uv run amamizu study "studies\2026-09_○○団地_調整池_台風25号"
```

期間の値が `studies\_jma\` になければ、3 の取得のコマンドを示してエラーで止まる。

### 5 結果を読む

出力ファイルは例1と同じである。
要約（`out\design_summary.md`、`.pdf`）には、時刻と一緒に日時も書かれる（時刻0分は 2026-09-20 00:00）。

| 項目 | 値 |
| --- | ---: |
| 実測降雨 | 千葉 10分値 2026-09-20〜2026-09-22 |
| 観測値 | studies/_jma/千葉_47682 |
| 時刻0分 | 2026-09-20 00:00 |
| 最大流入量 | 0.3067 m^3/s（2450 分、2026-09-21 16:50） |
| 最大放流量 | 0.0498 m^3/s（2480 分、2026-09-21 17:20） |
| 最大水位 | 12.0000 m（2480 分、2026-09-21 17:20） |
| 容量（満水位 12.000 m まで） | 2340.0 m^3 |
| 溢水量 | 532.8 m^3 |
| 判定（溢水） | N.G（溢れる） |

例1の調整池は、台風25号の千葉の降雨で満水位に達し、532.8 m^3 溢れた（実行の最後にも「注意:」として表示される）。
水位がいつ上がり、どれだけ満水が続いたかは `water_level.png` と `route.csv` で確かめる。

10分値に欠測（品質 `missing`）の区間や、取得していない日があると、その区間を 0 mm として計算し、要約に「欠測の時間」「取得していない時間」の行が出力される。
「取得していない時間」は、取得していない日か取得に失敗した日である。`start`・`end` と取得した期間が合っているかを確かめ、3 のコマンドを実行し直して取得する。
