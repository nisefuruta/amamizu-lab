# 条件設定

検討ごとの条件は、`studies/<検討>/study.json` に書く。
設計の検討（`kind: design`）は、[WebGUI](WebGUI.md) で入力すれば study.json を書いて保存するので、手で書かなくてよい。
手引の定数（強度式、放流の係数、許容放流比流量、地区の割り当て）は、検討のフォルダの `studies/_guideline/` のファイル（`chiba_2006.json`）に書く。
この文書では、それぞれの項目の意味と、値の決め方を説明する。
設計の検討（貯留追跡計算）の項目を先に書き、検証の例（貯留施設の検証、降雨強度の検証）の項目は、後ろの「[検証の例](#検証の例)」にまとめている。
計算の式は [厳密計算](厳密計算.md) にある。

## study.json の共通の項目

| 項目 | 意味 |
| --- | --- |
| `kind` | 検討の種類。`design`（設計の検討。調整池の貯留追跡計算）、`storage`（貯留施設の検証。手引どおりに計画した貯留施設を、実測降雨で確かめる）、`return_period`（降雨強度の検証。基準の降雨強度を、実測の年最大値で確かめる） |
| `guideline` | 使う手引の定数。必ず書く。`studies/_guideline/` のファイルの名前（`chiba_2006`）、`.json` のパス（検討フォルダから見た相対パスか絶対パス）、または `null`（手引を使用しない。`design` だけ）。書いていなければエラーで止まる。WebGUI の複製と `amamizu event-studies` は、相対パスを新しい検討から見たパスに直して書く（複製で `input/` の中のファイルを指しているときは、コピーした `input/` のファイルを指す） |
| `title` | 検討の題名。WebGUI の見出しと、レポートの見出しに使う |

設計の検討にレポートはない。検証の例（`storage`、`return_period`）は、レポートを `out/report.md` に出力する（保存先を変えるときは、コマンドの `--report <パス>` で指定する。設計の検討に `--report` を付けるとエラー）。

study.json に、この文書にない項目や、扱えない `kind` があると、`amamizu study` はエラーで止まる（WebGUI では、設計の検討なら、その項目を検討の画面の上部に表示する）。
入れ子の項目（`pond.table.level_col` など）や `conditions` の中の項目も同じで、不明な項目があればエラーになる。
値の型も確かめる。数の項目に `"1.0"` のような文字列や `true` を書く、文字列の項目に数を書く、整数の項目（`tc_min` など）に `10.0` や `10.5` を書く、とエラーになる。
強度式の `n` は、数か分数の文字列（`"3/4"`）で書く。
整数で書く項目は次のとおり。

- 設計の検討: `tc_min`、`end_min`、`rain.hours`、`rain.round_digits`、`rain.guideline.return_period`
- 貯留施設の検証: `conditions.tc_min`、`conditions.return_period`、`conditions.tail_hours`、`conditions.dry_gap`、`long_record.end_year`、`long_record.starts` の各地点の値
- 降雨強度の検証: `standard_period`、`duration_min`、`last_year`

`true`・`false` を書けるのは `events[].in_report`・`events[].overflow_detail`・`inflow_csv.reverse` だけで、これらの項目は `true` か `false` で書く（`"false"` のような文字列はエラー）。

エラーで止まるとき、amamizu コマンドは理由を「エラー（放流施設）: オリフィスの敷高 8 m が池底 9.0 m より低いです。敷高を池底以上にしてください。」の形で表示し、終了コード1で終わる。
括弧の中は、設計の検討で誤りのある項目のまとまり（WebGUI のタブの名前）である。
pandas や Python が発生させた誤りのように、amamizu が理由の文を書いていない誤りは、原因をたどれるよう Python の経過（Traceback）ごと表示する。

## 設計の検討（kind: design）

実際の調整池の厳密計算である。
流入、池、放流施設、計算の種類を書く。
計算の方法は [厳密計算](厳密計算.md#9-設計の厳密計算を行う)、入力ファイルの形式は [データの整理](データの整理.md#設計の検討の入力ファイル) にある。

計画降雨（手引の地区の式）と区域から流入を作り、表の池とオリフィス・洪水吐で追跡する例:

```json
{
  "kind": "design",
  "title": "○○団地 調整池",
  "guideline": "chiba_2006",
  "tc_min": 10,
  "rain": {"guideline": {"district": "千葉", "return_period": 50}, "shape": "rear"},
  "catchments": [
    {"name": "浸透なし区域", "area_ha": 2.10, "f": 0.9},
    {"name": "浸透あり区域", "area_ha": 1.35, "f": 0.8}
  ],
  "pond": {"table": {"file": "input/pond.csv"}},
  "orifice": {"sill_m": 16.0, "width_m": 0.209, "height_m": 0.209},
  "spillway": {"crest_m": 22.5, "width_m": 1.0},
  "allowable_q_m3s": 0.235
}
```

ハイドログラフを与え、最大放流量が目標値になる円形のオリフィスの直径を求める例:

```json
{
  "kind": "design",
  "guideline": "chiba_2006",
  "tc_min": 20,
  "inflow_csv": {"file": "input/hydrograph.csv", "time_col": "時刻_分", "q_col": "流入量_m3s"},
  "pond": {"table": {"file": "input/pond.csv", "level_col": "水位H", "area_col": "面積F", "volume_col": "容量V"}},
  "orifice": {"sill_m": 24.0, "shape": "circle"},
  "mode": "size_orifice",
  "target_q_m3s": 6.0
}
```

実測降雨（`studies/_jma/` に取得した10分値）を区域に降らせ、柱状の池で追跡する例:

```json
{
  "kind": "design",
  "guideline": "chiba_2006",
  "tc_min": 10,
  "observed_rain": {"station": "千葉", "series": "tenmin", "start": "2013-10-15", "end": "2013-10-16"},
  "catchments": [{"name": "区域", "area_ha": 1.0, "f": 0.9}],
  "pond": {"prismatic": {"area_m2": 600.0, "hwl_m": 2.0}},
  "orifice": {"sill_m": 0.0, "width_m": 0.08, "height_m": 0.08}
}
```

| 項目 | 既定値 | 意味 |
| --- | --- | --- |
| `created` | | 作成日時（`2026-09-24T10:30:00` の形）。WebGUI で作るか複製するか、`amamizu event-studies` で作ると書き込み、一覧の並び順に使う。なければフォルダの作成日時を使う。日時として読めない値のときもフォルダの作成日時を使い、WebGUI の一覧のその行に値と書き方を表示する |
| `tc_min` | 10 | 洪水到達時間 分。計画降雨の区切りと追跡の刻みに使う。計画降雨の継続時間（`rain.hours` を分に直した値）を割り切る整数。実測降雨のときは10の倍数 |
| `rain.guideline` | | 手引の強度式を使う。`district`（地区）と `return_period`（確率年） |
| `rain.formula` | | 強度式を直接書く。`type`（`talbot`、`sherman`、`kuno_ishiguro`、`cleveland`、`kuno_ishiguro_n`）と、その方式の係数 `a`、`b`、`n`（n は `"3/4"` のような分数の文字列か数値）。方式と係数は [厳密計算](厳密計算.md#1-確率降雨強度式) |
| `rain.shape` | （必須） | 降雨波形。`rear`（後方集中型、手引 図5－1）か `center`（中央集中型） |
| `rain.round_digits` | 丸めない | 区間の降雨強度（mm/h）を小数点以下この桁に四捨五入し、丸めた値で流入量を計算する。0以上の整数 |
| `rain.hours` | 24 | 計画降雨の継続時間 時間 |
| `catchments` | | 区域のリスト。各区域に `name`、`area_ha`（面積 ha）、`f`（流出係数）。流入量は区域ごとの合計。区域ごとの浸透施設は、区域の `infiltration`（書き方は最上位の `infiltration` と同じ）に書く。書いた区域が浸透処理区域、書かない区域は無処理区域（[厳密計算](厳密計算.md#浸透一定量差し引き)） |
| `inflow_csv` | | ハイドログラフの CSV。`file`、`time_col`、`q_col`、`rain_col`（任意）、`reverse`（任意） |
| `observed_rain` | | 実測降雨。`studies/_jma/` に取得済みの値を使う。`station`（地点名）、`series`（`tenmin` 10分値か `hourly` 時間値）、`start`・`end`（開始日と終了日。`2013-10-15` の形。その日の 0:00〜24:00 を含む）の4つを必ず書く。取得の手順と欠測の扱いは [データの整理](データの整理.md#設計の検討の実測降雨) |
| `pond.prismatic` | | 柱状の池。`area_m2`（面積）、`hwl_m`（満水位＝深さ）。水位は池底からの水深で、敷高も池底からの高さで書く（[厳密計算](厳密計算.md#高さの基準と池底とオリフィスの高さ関係)） |
| `pond.table` | | 池の表の CSV。`file`、`level_col`、`area_col`、`volume_col`、`hwl_m`（満水位。省略時は表の最上段）。面積と容量はどちらか一方を省ける（[データの整理](データの整理.md#設計の検討の入力ファイル)）。水位は絶対標高でも相対標高でもよく、敷高・満水位・ポンプの水位も同じ基準で書く（[厳密計算](厳密計算.md#高さの基準と池底とオリフィスの高さ関係)） |
| `orifice` | | オリフィス。`sill_m`（敷高）、`shape`（`rect` 長方形／`circle` 円形。省略時 `rect`）、寸法（`rect` は `width_m` と `height_m`、`circle` は `diameter_m`）。`mode: size_orifice` では寸法を書かない |
| `orifices` | | オリフィスのリスト（2段のオリフィスなど。各オリフィスの書き方は `orifice` と同じ）。放流量は各オリフィスの和。`orifice` とどちらか一つを書く。`mode: route` だけ |
| `spillway` | なし | 洪水吐。`crest_m`（敷高）、`width_m`（幅） |
| `pump` | なし | ポンプ。`levels_m`（水位のリスト）と `q_m3s`（排水量のリスト）の表を線形補間する。最初の水位より下は0、最後の水位より上は最後の排水量。排水量は水位とともに減らないこと。最初の水位は池底以上（排水量が正なら池底より上） |
| `judge.storage_margin_m3` | なし | 容量の余裕の判定。容量 ≧ 最大貯留量＋この値なら O.K |
| `infiltration` | なし（浸透なし） | 区域全体で1つの浸透（一定量差し引き）。書き方は次の表。区域ごとの浸透（`catchments` の各区域の `infiltration`）と両方は書けない |
| `mode` | `route` | `route` は与えたオリフィスで追跡する。`size_orifice` は最大放流量が `target_q_m3s` になるオリフィス（`rect` は正方形の一辺、`circle` は直径）を求めて追跡する |
| `target_q_m3s` | | `size_orifice` の目標の最大放流量 m^3/s（許容放流量など）。`size_orifice` では必ず書く。グラフの許容放流量の線にも使う |
| `allowable_q_m3s` | なし | 許容放流量 m^3/s（`mode: route` のとき任意）。要約とグラフに書き、判定の「放流量」に入る。最大放流量が超えたら判定の「放流量」と「総合」を N.G にし、「注意:」を表示する |
| `end_min` | 流入の期間＋18時間 | 追跡の終了時刻 分。計画降雨24時間なら2520分 |

浸透（最上位か区域の `infiltration`）は、設計浸透量を直接書くか、設計浸透強度を書くか、浸透施設を書く（どれか一つ）。書かなければ浸透は考えない。

| 項目 | 意味 |
| --- | --- |
| `rate_m3s`、`void_storage_m3` | 設計浸透量 m^3/s と空隙貯留量 m^3 を直接書く（`void_storage_m3` は任意、既定0） |
| `intensity_mmh`、`void_storage_m3` | 設計浸透強度 mm/h（設計浸透量 m^3/h ＝ 強度 × 浸透処理面積 ha × 10。浸透処理面積は区域ごとなら区域の面積、最上位なら区域の合計）と空隙貯留量 m^3。ハイドログラフの流入では使えない |
| `facilities` | 浸透施設のリスト。各施設に次の項目を書く |
| 　`name` | 施設の名前（要約に書く） |
| 　`specific_m2` または `shape` | 比浸透量 K（m^2）を直接書くか、`shape` に種類 `kind` と寸法（`H_m` 設計水頭、`W_m` 幅、`D_m` 直径、`L_m` 延長）を書いて式で求める。種類と式は [厳密計算](厳密計算.md#浸透一定量差し引き) |
| 　`permeability` | 飽和透水係数。`value` と `unit`（`m/h`、`m/s`、`cm/s`） |
| 　`count` | 数量（個、m、m^2 など、比浸透量の単位に合わせる） |
| 　`factors` | 影響係数。`clogging` 目づまり、`groundwater` 地下水位、`safety` 安全率 α（3つとも書く。0 より大きく 1 以下。3つを掛け合わせる） |
| 　`void_parts` | 1単位あたりの空隙貯留の部分のリスト（`volume_m3` 体積、`porosity_pct` 空隙率%）。任意 |

流入は `rain`（と `catchments`）、`observed_rain`（と `catchments`）、`inflow_csv` のどれか一つ、池は `pond.prismatic` か `pond.table` のどちらか一つを書く。
2つ以上書いた場合や、どれも書いていない場合はエラーで止まる。

次の場合もエラーで止まる。

- `rain.shape` がない、`rain.hours` が0以下
- `rain.formula.type` がないか扱えない種類、その方式で使う係数がない、その方式で使わない係数を書いた、`a` が0以下、分母 t^n＋b が0以下になる
- 計画降雨・実測降雨で区域（`catchments`）がない、区域の面積が0以下、流出係数が0以下か1より大きい、区域の名前が重なっている
- `inflow_csv` と `catchments` を両方書いた
- ハイドログラフの流入量・降雨強度に空欄か負の値がある
- `orifice` と `orifices` を両方書いた、`size_orifice` でオリフィスを2つ以上書いた
- ポンプの表の水位と排水量が同じ個数で2点以上ない、空欄か数でない値がある、水位が後ろほど高くなっていない、排水量が負か水位とともに減る
- 浸透で、`rate_m3s`・`intensity_mmh`・`facilities` のうち2つ以上を書いた、`facilities` と `void_storage_m3` を両方書いた、浸透施設に `specific_m2` と `shape` を両方書いたかどちらも書いていない、飽和透水係数の `unit` が `m/h`・`m/s`・`cm/s` でない、比浸透量の式の適用範囲外、その種類で使わない寸法を書いた
- オリフィスの敷高が池底より低い、洪水吐の敷高がオリフィスの敷高より低い、ポンプが池底で排水する
- 追跡の終了時刻が流入の期間より短い、tc で割り切れない
- ハイドログラフの時刻が tc, 2tc, 3tc … になっていない
- `observed_rain` の `station`・`series`・`start`・`end` のどれかがない、`series` が `tenmin`・`hourly` でない、実測降雨で tc が10の倍数でない
- `studies/_jma/` にその地点のフォルダがない、同じ地点名のフォルダが2つある、その地点の値の種類（10分値・時間値）を取得していない
- `observed_rain.start`・`end` を日付として読めない、`start` が `end` より後
- 期間の値が `studies/_jma/` に1つもない（取得のコマンドを示す。期間の途中の取得していない区間は 0 mm として計算する）
- `size_orifice` で、目標に達するオリフィスがない（目標の最大放流量にするオリフィスで池が溢れるときは、エラーにせず、溢れなくなる面積の倍率を要約に示して判定を N.G にする）
- オリフィスの形と寸法の項目が合わない（`rect` に `diameter_m`、`circle` に `width_m` など）、`route` で寸法がない、`size_orifice` で寸法を書いた
- `size_orifice` で `allowable_q_m3s` を書いた（目標値が許容放流量になる）、`route` で `target_q_m3s` を書いた
- `mode` が `route`・`size_orifice` でない、`size_orifice` で `target_q_m3s` がないか0以下、`judge.storage_margin_m3` が負
- グラフの文字が読めなくなる場合（[厳密計算](厳密計算.md#9-設計の厳密計算を行う)）

与えたオリフィスで池が溢れた場合（`mode: route`）は、計算を止めずに溢水量を要約に書き、「注意:」として表示する。
重力加速度と放流係数は `guideline` で選んだ手引の定数のファイルの `hydraulics` を使う。

### 手引を使用しない検討

`guideline` を `null` にすると、手引の定数のファイルを使わずに計算する。
放流の係数は study.json の `hydraulics` に書き、計画降雨は `rain.formula`（強度式の種類と係数）で書く。

```json
{
  "kind": "design",
  "title": "○○団地 調整池",
  "guideline": null,
  "hydraulics": {"g": 9.8, "c_weir": 1.8, "c_orifice": 0.6},
  "tc_min": 10,
  "rain": {"formula": {"type": "cleveland", "a": 2439, "b": 11.9, "n": "3/4"}, "shape": "rear"},
  "catchments": [{"name": "開発区域", "area_ha": 2.0, "f": 0.8}],
  "pond": {"prismatic": {"area_m2": 600.0, "hwl_m": 2.0}},
  "orifice": {"sill_m": 0.0, "width_m": 0.08, "height_m": 0.08}
}
```

| `hydraulics` の項目 | 意味 |
| --- | --- |
| `g` | 重力加速度 m/s^2。オリフィスの式に使う |
| `c_weir` | 越流係数。水深がオリフィスの高さの1.2倍以下のときの式 Q＝C·B·h^1.5 の C。洪水吐の式にも使う |
| `c_orifice` | オリフィスの流量係数。水深がオリフィスの高さの1.8倍以上のときの式 Q＝C·A·√(2gh) の C |

次の書き方はエラーで止まる。

- `guideline` が `null` で、`hydraulics` がない
- `guideline` が `null` で、`rain.guideline`（手引の地区と確率年）を書いた
- `guideline` に手引の定数を書き、`hydraulics` も書いた

## 流出の条件

流出係数 f は、手引 表5－1 により、不浸透域を1.0、浸透域を0.6として面積で加重平均する。

```
f = 1.0 × 不浸透面積率 + 0.6 × (1 - 不浸透面積率) = 0.6 + 0.4 × 不浸透面積率
```

不浸透面積率50%で f＝0.8、75%で f＝0.9 になる。
手引は上限を0.9とすることができるとしている。
早見表の適用範囲（不浸透面積率30〜75%）は f＝0.72〜0.90 にあたる。
study.json には f を直接書く（設計の検討は `catchments` の区域ごとの `f`、貯留施設の検証は `conditions.f`）。

洪水到達時間は `tc_min`（既定10分）で変えられる（[厳密計算](厳密計算.md#2-洪水到達時間-tc-と計算の刻み)）。

## 条件を変えたとき

設計の検討で条件を変えた別のケースは、WebGUI の「複製する」で新しい検討を作る（[WebGUI](WebGUI.md#検討の一覧)）。

## 手引の定数（chiba_2006.json）

手引の定数のファイルは `studies/_guideline/` に置く。項目の説明と雛形（`_template.json`）も同じフォルダにある。
WebGUI の「手引の定数」には、このフォルダのファイルの名前と「使用しない」が表示される（名前が `_` で始まるファイルは表示されない）。
表の「使い道」のうち、貯留施設の検証、地点ごとの設計の検討、レポートは、検証の例（[検証の例](#検証の例)）のものである。

| キー | 内容 | 出典 | 使い道 |
| --- | --- | --- | --- |
| `name` | 手引の名前。必須 | | WebGUI と `amamizu verify` の表示、エラーの文 |
| `formulas` | 地区→確率年→`[a, n, b]` の確率降雨強度式。n は分数の文字列 | 資料－1 | 計算（計画降雨） |
| `formula_table`、`formula_table_conditions` | 式の検算用の表の値と、その条件（`t_min` は値の並びの継続時間 分で、千葉県は 10、60、1440。`digits` は表の値の小数の桁数で、千葉県は 1） | 資料－1 | 照合（`amamizu verify` で、強度式の強度を `digits` の桁に丸めて表の値と照合する） |
| `qc_min` | 許容放流比流量の下限 m^3/s/ha。`default` と地区ごとの例外 | 第5条(3) | 計算（貯留施設の検証と、地点ごとの設計の検討のモデル施設の許容放流量）、照合（早見表と比べる列を選ぶ） |
| `runoff` | 流出率（不浸透域、浸透域、上限） | 表5－1 | レポート（流出係数から不浸透面積率を求める、流出係数が範囲内かを確かめる）、照合（早見表と比べる行を選ぶ） |
| `district_of_station` | 観測所→地区の割り当て | 図5－2 の適用範囲 | 計算（観測所の地区の強度式と許容放流比流量を選ぶ） |
| `default_district`、`district_term` | WebGUI で計画降雨を選ぶときの地区の初期値と、区域の呼び方（WebGUI のラベル、要約と計画降雨の説明、レポートの見出しと表の列名、検討の題名に使う）。なければ式の表の最初の地区と「地区」 | | WebGUI とレポートの表示 |
| `hayami`、`hayami_imp`、`hayami_f`、`hayami_conditions` | 必要洪水調節容量早見表と、その計算条件（`pond_area_ratio` は池の面積の開発面積に対する割合、`tc_min` は洪水到達時間 分、`return_period` は確率年。千葉県は 0.05、10、50）。任意 | 資料－2 | 照合（`amamizu verify` と貯留施設の検証のレポートで、計算結果と比べる） |
| `infiltration_table`、`infiltration_table_rows`、`infiltration_table_conditions` | 浸透ありの必要洪水調節容量の表と、その計算条件（開発面積 1.0 ha、流出率 0.8、池の面積は開発面積の5%、洪水到達時間10分、1/50）。任意 | 第10条 表10－2 | 照合（`amamizu verify` で計算結果と比べる） |
| `hydraulics` | 重力加速度 `g`、越流係数 `c_weir`、オリフィスの流量係数 `c_orifice`（千葉県は 9.8、1.8、0.6）。必須 | | 計算（放流量） |
| `infiltration_notes` | WebGUI の浸透施設の欄の近くに表示する文。`factors` は影響係数、`void` は空隙貯留量。任意 | 解説 p.32・p.33 | WebGUI の表示 |
| `region`、`issuer`、`citation`、`cite` | レポートの文に使う語（観測所の地域、強度式の発行者の略称、出典の書き方、各項目の手引の箇所） | | レポートの文 |
| `…_note` | 各項目の説明 | | 説明を自由に書く項目（計算に影響しない） |

`hydraulics`、`runoff`、`infiltration_notes`、`…_conditions`、`hayami` と `infiltration_table` の地区ごとの項目（`qc`、`v`）には、決まった項目だけを書く。ほかの項目があれば、読み込むときにエラーにする。

地区の割り当ては、観測所の位置が図5－2 のどの地区の範囲にあるかで決める。
新しい観測所を使うときは、`district_of_station` に足す。
手引にない地区名は、エラーで止まる。
レポートの地区の並びは `formulas` に書いた順である。

他の基準を使うときは、同じ形の JSON を `studies/_guideline/` に置き（またはパスで指定し）、study.json の `guideline` で選ぶ。
早見表のない基準では、早見表の項目を書かない。
`amamizu verify --guideline <名前>` で強度式の係数を表の値と照合する（早見表がなければ強度式だけを照合する）。
検証の例のレポートを作るときは `region`、`issuer`、`citation`、`cite` も必要で、足りなければエラーで止まる。

計算の方法は次のものに限られる。基準の方法がこれと違う場合は、JSON を用意しても、手引を使用しない検討にしても計算できない。

| 項目 | 計算の方法 |
| --- | --- |
| 強度式 | r＝a/(t^n＋b)。t は分。1つの地区と確率年に式は1つ（継続時間の範囲で式が変わる基準、日雨量から求める式は書けない） |
| 計画降雨の波形 | 後方集中型、中央集中型 |
| 流出量 | 合理式連続モデル |
| オリフィス | 水深が高さの1.2倍以下は越流の式、1.8倍以上はオリフィスの式、その間は直線で補間 |
| 浸透 | 一定量差し引き |

強度式を書けない基準の計画降雨は、その降雨から求めたハイドログラフを流入に使う（`inflow_csv`）。

## 検証の例

ここから後ろは、検証の例（`studies/` の貯留施設の検証と、降雨強度の検証）の study.json の項目である。
共通の項目（`kind`、`guideline`、`title`）と、項目や値の型の確かめ方は、[study.json の共通の項目](#studyjson-の共通の項目) と同じである。
貯留施設の検証と降雨強度の検証は、必ず書く項目がなければ、その項目名を示してエラーで止まる。貯留施設の検証は `title`、`conditions`、`long_record`（`starts`、`end_year`）、`partial_year`（`from`、`to`）、`events`（各降雨の `name`、`stations`、`start`、`end`）、降雨強度の検証は `title`、`standard_period`、`duration_min`、`last_year`、`event`（`label`、`month`）である。

### 貯留施設の検証（kind: storage）

```json
{
  "kind": "storage",
  "title": "県の手引きによる貯留施設の検証",
  "guideline": "chiba_2006",
  "conditions": {"f": 0.8, "depth": 2.0, "area_ha": 1.0, "return_period": 50, "tail_hours": 48,
                 "fill_ratio": 0.5, "dry_gap": 2, "tenmin_from": "2008-01-01", "tenmin_fill": 0.7},
  "long_record": {
    "note": "標本の開始年を決めた理由",
    "station_kind": "官署",
    "starts": {"千葉": 1967, "館山": 1969, "勝浦": 1969, "銚子": 1964},
    "end_year": 2025
  },
  "partial_year": {"from": "2026-01-01", "to": "2026-09-22"},
  "events": [
    {"name": "千葉豪雨", "stations": ["千葉", "館山", "勝浦", "銚子", "佐倉"], "start": "2026-08-13", "end": "2026-08-15", "in_report": true},
    {"name": "台風25号", "stations": ["千葉", "館山", "勝浦", "銚子", "佐倉"], "start": "2026-09-20", "end": "2026-09-22"}
  ]
}
```

#### conditions

モデル施設と判定の条件である。
`conditions` は必ず書く（すべて既定値にするときは `{}`）。書いていなければエラーで止まる。
中の項目を省略すると、表の既定値になる。

| 項目 | 既定値 | 意味 |
| --- | ---: | --- |
| `f` | 0.8 | 流出係数（決め方は [流出の条件](#流出の条件)） |
| `depth` | 2.0 | 池の深さ（満水位）m |
| `area_ha` | 1.0 | 開発面積 ha |
| `return_period` | 50 | 計画降雨の確率年 |
| `tail_hours` | 48 | 降雨の後に足す無降水の時間。池の水位が下がりきるまで追跡する |
| `fill_ratio` | 0.5 | 候補降雨の基準。総雨量が容量のこの割合に相当する雨量以上の降雨を計算する |
| `dry_gap` | 2 | 降雨を区切る無降水の日数（日別値が欠測の日は無降水に数えない） |
| `tenmin_from` | 2008-01-01 | 10分値で計算し直す降雨の開始日の下限 |
| `tenmin_fill` | 0.7 | 10分値で計算し直す降雨の最大貯留率の下限 |
| `tc_min` | 10 | 洪水到達時間 分。モデル施設の計画降雨の区切りと追跡の刻み。10・20・30・60 のどれか（10分値を tc ごとに合計する） |

結果の表の列名（`6h_1/50_mm` など）、公表値との照合、レポートの表記は、`return_period` から作る。
例えば30にすると、列名は `6h_1/30_mm` になり、計画の雨量も1/30の強度式から求める。

`depth` と `area_ha` の組み合わせによっては、施設の寸法が決まらないことがある。
例えば、満水位が浅すぎてオリフィスを最大にしても許容放流量に達しない場合や、必要な池の面積が探索の範囲（10〜100,000 m^2）を超える場合である。
このときは、範囲の端の寸法で計算を続けず、エラーで止まる。

#### 池の条件

モデル施設の池は柱状（深さによらず面積が一定）で、浸透はないものとする。
深さ `depth` を決め、地区の計画降雨で最大水位がちょうど満水位に達する池の面積を求める。
こうすると、手引どおりに1/`return_period` で計画した施設と同じ容量になる（下の丸めの分だけ大きくなる）。

放流オリフィスは正方形で、下端を池底に置く。
オリフィスの寸法は、満水位での放流量が許容放流量になるように決める。
許容放流量は、許容放流比流量の下限（手引 第5条(3)）×開発面積である。
下限は地区で異なり、勝浦地区と館山地区が0.035 m^3/s/ha、その他の地区が0.025 m^3/s/ha である（`chiba_2006.json` の `qc_min`）。

ちょうど達する寸法は、四捨五入すると判定が揺れるので、判定が変わらない向き（安全側）に丸めてモデル施設にする。

1. オリフィスは1mm単位で切り捨てる（大きくすると許容放流量を超える）
2. そのオリフィスで、計画降雨の最大水位がちょうど満水位になる池の面積を求め直し、1m^2単位で切り上げる

計画容量は、丸めた池の満水位までの容量（面積×深さ）である。
実測降雨は、このモデル施設に与え、設計の検討（`kind: design`）と同じ方法で計算する。

#### 降雨の標本の条件

| 項目 | 決め方 |
| --- | --- |
| `tail_hours` | 満水の池が十分下がる時間にする。モデル施設では48時間で容量の3%以下まで下がる |
| `dry_gap` | 前の降雨の水が池に残らない日数にする。`tail_hours` と対応させる |
| `fill_ratio` | 溢れる降雨を取りこぼさない値にする。0.5 なら、外れた降雨は池の半分にも達しない |
| `tenmin_from` | 10分値が取得できる最初の日（2008年）にする |
| `tenmin_fill` | 時間値と10分値の最大貯留率の差より十分大きな余裕をとる |

候補降雨の基準雨量の式と、降雨の区切り方は [データの整理](データの整理.md#候補降雨の選定) にある。

#### long_record

長期記録の対象地点と期間である。

- `starts`：地点ごとの標本の開始年。地点の名前は `chiba_2006.json` の `district_of_station` にあるものを使う。
- `end_year`：標本の最後の年。途中の年は含めない。
- `station_kind`：地点の種別（官署、アメダスなど）。レポートの見出し（「官署4地点の長期記録」）に使う。省略すると「4地点の長期記録」になる。
- `note`：説明を自由に書く項目（計算に影響しない）。開始年を決めた理由などを書く。

開始年は、時間値の合計が日別値の合計と1mm以内で一致する年からにする（[データの整理](データの整理.md#データの整合の確認)）。
開始年の1月1日から `end_year` の12月31日までに日別値のない日があると、エラーで止まる。

#### partial_year

標本とは別に示す途中の年の期間（`from`〜`to`）である。
`from`・`to` は `2026-01-01` の形で書く。違う形ならエラーで止まる。
候補降雨はすべて10分値で計算する。

#### events

多地点で同時に確かめる降雨のリストである。降雨ごとに `out/event_<開始日>.tsv`（例: `event_20260813.tsv`）を書く。
`stations`（地点名のリスト）の地点を、`start`〜`end` の期間の10分値（`studies/_jma/` の値。[データの整理](データの整理.md#studies_jma-のファイル)）で計算する。
`stations` が空のリストか、同じ地点が2回以上あるなら、エラーで止まる。
`name` は WebGUI での表の名前とレポートの見出しに使う（「千葉豪雨（2026年8月13〜15日）18地点」。期間と地点数は計算から作る）。
レポートに表を載せる降雨は `"in_report": true` にする（1つ以上。1つもなければ、レポートを作るときにエラーで止まる）。
表は3節から study.json の順に1節ずつ並べる（千葉豪雨が3節、台風25号が4節）。
`"overflow_detail": true` の降雨は、表で溢れた地点の貯留施設の水位の節も載せる
（最初の24時間で上がった水位とその後の最小、満水位に達した時刻、降り始めから降り終わりまでの時間を書いた文、地点ごとの満水位に達した時刻・満水の時間・溢水量の表、1時間ごとの雨量と水位の図。
図は降雨の開始を0時間とし、どの地点も同じ横軸にする。水位の図には、WebGUI の試算の比較と同じく、計画降雨を与えたときの水位を参考に重ねる）。
載せる地点は表で溢れた地点なので、`"in_report": true` のない降雨に付けるとエラーで止まる。
レポートの節は、モデル施設、計画降雨、降雨の表、溢れた地点の水位、長期記録、溢水した降雨と満水に近い降雨、欠測のある降雨の順に並べる。
開始日が同じ降雨があると、表の名前が重なるのでエラーで止まる。
10分値が期間の日数分そろっていない地点があると、エラーで止まる。

#### レポートの文

レポートの文に記載する値は、どれも条件から作る。
開発面積、流出係数と不浸透面積率、確率年、許容放流比流量の出典、降雨の名前と期間、地点数、10分値で計算し直す条件、表に載せる最大貯留率の下限（`fill_ratio` と同じ）、早見表との照合の件数と差が対象である。
不浸透面積率は流出係数から逆算するので、流出係数が手引の流出率（浸透域0.6〜不浸透域1.0）の範囲外なら、レポートを作らずエラーで止まる。
早見表に `f` の行がなければ、レポートの早見表の列と照合の文は記載しない。
降雨の表には「欠測の時間」の列があり、最後の節に欠測のある降雨をまとめる（[データの整理](データの整理.md#データの整合の確認)）。

### 降雨強度の検証（kind: return_period）

```json
{"kind": "return_period", "title": "県の手引きによる降雨強度の検証", "guideline": "chiba_2006", "standard_period": 10, "duration_min": 10, "last_year": 2025,
 "event": {"label": "2026年8月13〜15日", "month": "2026年8月"}}
```

| 項目 | 意味 |
| --- | --- |
| `standard_period` | 基準にする確率降雨強度式の確率年（県の10年確率式なら10） |
| `duration_min` | 基準の強度を求める継続時間 分。10だけ扱える |
| `last_year` | 標本の最後の年。検証したい事象の年を含めない |
| `event.label`、`event.month` | 検証したい事象の期間の書き方。レポートの表の行名と列名に使う |

標本は年最大10分間降水量に固定されている。
計算の前に、`amamizu fetch <検討フォルダ> annual_max --stations <地点> …` で年最大値系列と観測史上順位を取得しておく（[年最大値系列の標本](データの整理.md#年最大値系列の標本)）。
`duration_min` が10以外ならエラーで止まる。

レポートの文（題名、地域、地点数、確率年、除いた年、事象の期間、出典）は、study.json と手引の定数から作る。
出典の取得日は、studies/_jma/ の年最大値系列と観測史上順位の取得日（地点のうち最も新しい日）である。
`title`、`event` がなければ、エラーで止まる。

継続時間は、先に「どの継続時間の強度か」を決めてから選ぶ。
継続時間の指定がない mm/hr は評価できない。
断面算定なら流達時間（外構は約10分）の強度である。
気象庁の最短は10分なので、流達時間が5分なら10分の強度は下限の値になる。
